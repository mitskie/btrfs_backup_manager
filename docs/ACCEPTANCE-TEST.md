# Приемочное тестирование Btrfs Backup Manager на реальной Btrfs

Инструкция выполняется НА ВАШЕЙ МАШИНЕ в изолированной тестовой среде.
Программная эмуляция не заменяет реальную Btrfs: все группы ниже
работают с настоящим ядром и настоящими утилитами.

## Как пользоваться инструкцией

1. Блоки команд копируются В ТЕРМИНАЛ ЦЕЛИКОМ. Каждый блок
   самодостаточен: все переменные он определяет сам, незаполненных путей
   нет. Не запускайте блоки построчно.
2. Каждая группа завершается строкой статуса: `УСПЕХ`, `ОШИБКА` или
   `ПРОПУЩЕНО`. **После статуса `ОШИБКА` НЕ переходите к следующей
   группе** — пришлите вывод целиком и дождитесь анализа.
3. После КАЖДОЙ группы остановитесь и пришлите вывод целиком.
4. Тестовая среда — отдельная файловая система Btrfs на loop-устройстве
   `/dev/loop0`, смонтированная в `/mnt/btrfs-test`. Рабочая файловая
   система `/dev/sda1` в тесте НЕ участвует. Это ПОДТВЕРЖДАЕТСЯ
   фактическими проверками группы 1: `findmnt` (точка монтирования),
   `btrfs filesystem show` по точке монтирования И по устройству,
   сверкой с ЗАРАНЕЕ ИЗВЕСТНЫМ UUID тестовой ФС (п. 4a) и
   `btrfs inspect-internal rootid`. UUID, обнаруженный на
   `/dev/loop0`, сам по себе эталоном НЕ является. При любом
   несовпадении группа 1 завершается `ОШИБКА`, и испытания
   останавливаются.
4a. Заранее известный UUID тестовой ФС. При подготовке тестовой среды
   запишите ее UUID: его печатает mkfs.btrfs, либо выполните
   `sudo btrfs filesystem show /dev/loop0` НА МОМЕНТ ПОДГОТОВКИ и
   сохраните вывод. Группа 1 сверит с этим UUID результат двух
   независимых запросов. При первом прогоне эталон берется из ввода
   оператора (или из файла прошлого прогона); файл эталона
   `/tmp/bbm-test-fs.uuid` записывается ТОЛЬКО после полного
   совпадения и НИКОГДА не перезаписывается; эталон — обычный файл,
   символическая ссылка (в том числе висячая) на его месте — ошибка:
   по ссылкам приемка не следует. Нет заранее известного
   UUID — группа 1 завершается `ОШИБКА`: независимого подтверждения
   нет, обнаруженный UUID эталоном не является.
5. Команды с `sudo` нужны потому, что: (а) тестовая Btrfs обычно
   смонтирована от root; (б) операции со снапшотами и
   `btrfs send/receive` требуют root. Что делает каждая команда,
   написано рядом.
6. Пароль GPG вводится скрыто (символы не отображаются) и в логи не
   попадает. Для теста придумайте простой пароль, например
   `acceptance-2026`, и используйте его на всех шагах одинаковый.
7. Программа скопирована в любое удобное место (пример —
   `/opt/btrfs-backup-manager`; обязательный путь НЕ требуется, см.
   docs/INSTALL.md). Ниже `/opt/btrfs-backup-manager` — замените на
   свой каталог при необходимости; структура каталога = структура ZIP.
8. Временные файлы приемки (перечни архивов, расшифрованные копии,
   поврежденные копии, диагностический отчет, файлы настроек групп
   14-15, манифест объектов группы 8) создаются ТОЛЬКО в служебном
   каталоге приемки с правами 700/600; группа 13 удаляет их. Файлы по
   фиксированным путям в `/tmp` не создаются никогда — кроме файла
   указателя (две строки: путь каталога приемки и уникальный случайный
   идентификатор запуска) и эталонного UUID, которые создаются
   атомарно (noclobber): если путь уже занят любым объектом — файлом,
   каталогом, символической ссылкой, в том числе висячей — отказ без
   перезаписи и без открытия существующего объекта на запись; никогда
   не перезаписываются. Временные файлы не создаются в
   `/mnt/btrfs-test` (кроме самих результатов операций, которые
   проверяются).
9. Тест никогда не перезаписывает и не удаляет существующие объекты:
   если целевой объект теста уже существует — группа останавливается с
   понятной ошибкой, существующие данные сохраняются. «Существует»
   значит любой объект: файл, каталог, символическая ссылка (в том
   числе висячая) — по ссылкам тест не следует.

## Группа 1. Подтверждение тестовой среды (только чтение)

- **Цель:** однозначно подтвердить параметры тестовой среды ДО любых
  изменяющих операций: точка монтирования, тип ФС, UUID, устройство,
  источник, отсутствие `/dev/sda1`.
- **Предварительные условия:** каталог `/mnt/btrfs-test` смонтирован
  (подготовка среды — вне рамок этой инструкции); программа скопирована
  в `/opt/btrfs-backup-manager`; известен UUID тестовой ФС, записанный
  при подготовке среды (п. 4a).
- **Команды** (только чтение + создание служебного каталога приемки
  `/tmp/bbm-acceptance.*` с правами 700, идентификатора запуска и
  файла указателя — каждое создание служебного файла атомарно
  (noclobber): отказ, если путь уже занят любым объектом, включая
  символическую ссылку (в том числе висячую); код возврата создания
  проверяется явно):

```bash
G1_STATUS="УСПЕХ"
# --- 1.0 служебный каталог приемки (временные файлы групп 4-15) ---
if [ -e /tmp/bbm-acceptance.dir ] || [ -L /tmp/bbm-acceptance.dir ]; then
  echo "1.0: ОШИБКА — /tmp/bbm-acceptance.dir уже существует (файл, каталог или символическая ссылка, включая висячую): предыдущий прогон не завершен. Выполните группу 13 того прогона или разберите вручную; существующий объект НЕ перезаписываю, по ссылкам не следую"
  echo "ГРУППА 1: ОШИБКА — испытания останавливаются"
  G1_STATUS="ОШИБКА"
else
  # идентификатор запуска генерируется ДО создания объектов: при отказе ничего не остается
  RUN_ID=$(head -c 16 /dev/urandom | od -An -tx1 | tr -d ' \n')
  if [ -z "$RUN_ID" ]; then
    echo "1.0: ОШИБКА — не удалось сгенерировать идентификатор запуска (/dev/urandom); продолжать небезопасно"
    echo "ГРУППА 1: ОШИБКА — испытания останавливаются"
    G1_STATUS="ОШИБКА"
  else
    BBM_ACC_DIR=$(mktemp -d /tmp/bbm-acceptance.XXXXXX)
    if [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
      echo "1.0: ОШИБКА — mktemp не создал служебный каталог (см. сообщение mktemp выше); продолжать небезопасно"
      echo "ГРУППА 1: ОШИБКА — испытания останавливаются"
      G1_STATUS="ОШИБКА"
    elif ! chmod 700 "$BBM_ACC_DIR"; then
      echo "1.0: ОШИБКА — chmod 700 для $BBM_ACC_DIR не выполнен; продолжать небезопасно"
      echo "ГРУППА 1: ОШИБКА — испытания останавливаются"
      G1_STATUS="ОШИБКА"
    elif [ -e "$BBM_ACC_DIR/run-id.txt" ] || [ -L "$BBM_ACC_DIR/run-id.txt" ]; then
      echo "1.0: ОШИБКА — $BBM_ACC_DIR/run-id.txt уже существует (в только что созданном каталоге); НЕ перезаписываю"
      echo "ГРУППА 1: ОШИБКА — испытания останавливаются"
      G1_STATUS="ОШИБКА"
    else
      # атомарное создание run-id.txt: noclobber (open с O_CREAT|O_EXCL) отказывает,
      # если путь занят ЛЮБЫМ объектом — файлом, каталогом, символической ссылкой
      # (в том числе висячей) — и не открывает существующий объект на запись;
      # проверка отсутствия выше — только диагностика: от гонки между ней и записью
      # защищает атомарный отказ. Код возврата проверяется явно.
      if ( set -o noclobber; printf '%s\n' "$RUN_ID" > "$BBM_ACC_DIR/run-id.txt" ); then
        # указатель: ДВЕ строки — путь каталога приемки и идентификатор запуска
        # (группы 9 и 13 сверят их перед удалением); тот же атомарный механизм
        if ( set -o noclobber; printf '%s\n%s\n' "$BBM_ACC_DIR" "$RUN_ID" > /tmp/bbm-acceptance.dir ); then
          echo "Каталог приемки: $BBM_ACC_DIR (права 700); идентификатор запуска: $RUN_ID; указатель /tmp/bbm-acceptance.dir создан атомарно (две строки)"
        else
          echo "1.0: ОШИБКА — указатель /tmp/bbm-acceptance.dir не создан атомарно (путь занят между проверкой и записью, в том числе символической ссылкой, или отказ записи); существующий объект НЕ перезаписан и НЕ удален"
          G1_STATUS="ОШИБКА"
        fi
      else
        echo "1.0: ОШИБКА — $BBM_ACC_DIR/run-id.txt не создан атомарно (путь занят между проверкой и записью или отказ записи); существующий объект НЕ перезаписан и НЕ удален"
        G1_STATUS="ОШИБКА"
      fi
    fi
  fi
fi

if [ "$G1_STATUS" = "УСПЕХ" ]; then
  # --- 1.1 версии инструментов ---
  id
  uname -r
  btrfs --version
  gpg --version | head -1
  gzip --version | head -1
  zstd --version 2>/dev/null || echo "zstd НЕ УСТАНОВЛЕН (группы 8-zstd, 10, 14 будут ПРОПУЩЕНО частично)"

  # --- 1.2 findmnt: ТОЧКА МОНТИРОВАНИЯ, тип ФС и источник монтирования ---
  FM_LINE=$(findmnt -n -o SOURCE,FSTYPE,TARGET /mnt/btrfs-test)
  FM_RC=$?
  if [ "$FM_RC" -ne 0 ] || [ -z "$FM_LINE" ]; then
    echo "1.2 findmnt: ОШИБКА — /mnt/btrfs-test не смонтирован"
    G1_STATUS="ОШИБКА"
  else
    FM_SOURCE=$(echo "$FM_LINE" | awk '{print $1}')
    FM_FSTYPE=$(echo "$FM_LINE" | awk '{print $2}')
    FM_TARGET=$(echo "$FM_LINE" | awk '{print $3}')
    echo "1.2 findmnt: источник=$FM_SOURCE тип=$FM_FSTYPE точка=$FM_TARGET"
    if [ "$FM_FSTYPE" = "btrfs" ] && [ "$FM_TARGET" = "/mnt/btrfs-test" ]; then
      case "$FM_SOURCE" in
        /dev/loop0|/dev/loop0\[*)
          echo "1.2: ОК — btrfs на /mnt/btrfs-test, источник монтирования /dev/loop0"
          ;;
        /dev/sda1*)
          echo "1.2: ОШИБКА — источник монтирования $FM_SOURCE — это РАБОЧАЯ ФС; СТОП"
          G1_STATUS="ОШИБКА"
          ;;
        *)
          echo "1.2: ОШИБКА — источник монтирования $FM_SOURCE (ожидался /dev/loop0); СТОП"
          G1_STATUS="ОШИБКА"
          ;;
      esac
    else
      echo "1.2: ОШИБКА — ожидался btrfs на /mnt/btrfs-test, фактически: $FM_LINE"
      G1_STATUS="ОШИБКА"
    fi
  fi
fi

if [ "$G1_STATUS" = "УСПЕХ" ]; then
  # --- 1.3 btrfs filesystem show по ТОЧКЕ МОНТИРОВАНИЯ: UUID и устройства ---
  FS_SHOW=$(sudo btrfs filesystem show /mnt/btrfs-test 2>&1)
  FS_SHOW_RC=$?
  echo "1.3 filesystem show (точка монтирования, rc=$FS_SHOW_RC):"
  echo "$FS_SHOW"
  FS_UUID=""
  if [ "$FS_SHOW_RC" -ne 0 ]; then
    echo "1.3: ОШИБКА — btrfs filesystem show не выполнен"
    G1_STATUS="ОШИБКА"
  else
    FS_UUID=$(echo "$FS_SHOW" | sed -n 's/^.*uuid: \([0-9a-f][0-9a-f-]*\).*$/\1/p' | head -1)
    FS_DEVICES=$(echo "$FS_SHOW" | grep -o '/dev/[a-zA-Z0-9/]*' | sort -u)
    echo "1.3: UUID тестовой ФС: $FS_UUID"
    echo "1.3: устройства тестовой ФС: $(echo $FS_DEVICES)"
    if echo "$FS_DEVICES" | grep -q '^/dev/sda1$'; then
      echo "1.3: ОШИБКА — /dev/sda1 входит в тестовую ФС; рабочие данные под угрозой; СТОП"
      G1_STATUS="ОШИБКА"
    elif echo "$FS_DEVICES" | grep -q '^/dev/loop0$'; then
      echo "1.3: ОК — устройства тестовой ФС: /dev/loop0 (без /dev/sda1)"
    else
      echo "1.3: ОШИБКА — /dev/loop0 не найден среди устройств ФС; СТОП"
      G1_STATUS="ОШИБКА"
    fi
  fi
fi

if [ "$G1_STATUS" = "УСПЕХ" ]; then
  # --- 1.3b Независимое подтверждение ЗАРАНЕЕ ИЗВЕСТНОГО UUID.
  #     Запрос по точке монтирования и запрос по устройству обращаются
  #     к одной и той же ФС: их совпадение между собой доказывает лишь
  #     самосогласованность и эталоном служить НЕ может. Эталон — UUID,
  #     известный ДО прогона: файл прошлого прогона (он записывается
  #     ТОЛЬКО после полного совпадения и никогда не перезаписывается)
  #     или ввод оператора (UUID записан при подготовке среды).
  #     Обнаруженный на /dev/loop0 UUID сам по себе эталоном НЕ является.
  #     Символическая ссылка на месте эталона (включая висячую) — ошибка:
  #     по ссылкам в /tmp приемка не следует.
  KNOWN_UUID=""
  if [ -L /tmp/bbm-test-fs.uuid ]; then
    echo "1.3b: ОШИБКА — /tmp/bbm-test-fs.uuid является символической ссылкой (включая висячую); по ссылкам не следую, эталон из нее не читаю. Удалите ссылку и укажите эталон (п. 4a)"
    G1_STATUS="ОШИБКА"
  elif [ -e /tmp/bbm-test-fs.uuid ] && [ ! -f /tmp/bbm-test-fs.uuid ]; then
    echo "1.3b: ОШИБКА — /tmp/bbm-test-fs.uuid существует, но не является обычным файлом; эталон из него не читаю"
    G1_STATUS="ОШИБКА"
  else
    if [ -f /tmp/bbm-test-fs.uuid ]; then
      KNOWN_UUID=$(cat /tmp/bbm-test-fs.uuid)
      echo "1.3b: эталон — файл прошлого прогона (/tmp/bbm-test-fs.uuid): $KNOWN_UUID"
    fi
    if [ -z "$KNOWN_UUID" ]; then
      read -r -p "Введите ЗАРАНЕЕ ИЗВЕСТНЫЙ UUID тестовой ФС (записан при подготовке среды, п. 4a; пустой ввод недопустим): " KNOWN_UUID
    fi
    if [ -z "$KNOWN_UUID" ]; then
      echo "1.3b: ОШИБКА — заранее известный UUID недоступен (нет файла прошлого прогона, оператор не ввел его). Независимого подтверждения НЕТ: обнаруженный UUID эталоном не является; СТОП"
      G1_STATUS="ОШИБКА"
    elif [ "$FS_UUID" != "$KNOWN_UUID" ]; then
      echo "1.3b: ОШИБКА — UUID по точке монтирования ($FS_UUID) не совпадает с заранее известным ($KNOWN_UUID): вы работаете НЕ с той файловой системой; СТОП"
      G1_STATUS="ОШИБКА"
    else
      FS_UUID_BY_DEV=$(sudo btrfs filesystem show /dev/loop0 2>/dev/null | sed -n 's/^.*uuid: \([0-9a-f][0-9a-f-]*\).*$/\1/p' | head -1)
      if [ -z "$FS_UUID_BY_DEV" ] || [ "$FS_UUID_BY_DEV" != "$KNOWN_UUID" ]; then
        echo "1.3b: ОШИБКА — UUID по устройству ('$FS_UUID_BY_DEV') не совпадает с заранее известным ('$KNOWN_UUID'); СТОП"
        G1_STATUS="ОШИБКА"
      else
        echo "1.3b: ОК — заранее известный UUID подтвержден ДВУМЯ независимыми запросами (точка монтирования и устройство): $KNOWN_UUID"
        if [ -e "$BBM_ACC_DIR/fs-uuid.txt" ] || [ -L "$BBM_ACC_DIR/fs-uuid.txt" ]; then
          echo "1.3b: ОШИБКА — $BBM_ACC_DIR/fs-uuid.txt уже существует (в каталоге приемки этого запуска); НЕ перезаписываю"
          G1_STATUS="ОШИБКА"
        else
          # атомарное создание (noclobber): отказ при занятом пути, без открытия
          # существующего объекта на запись; проверка выше — только диагностика
          if ( set -o noclobber; printf '%s\n' "$FS_UUID" > "$BBM_ACC_DIR/fs-uuid.txt" ); then
            :
          else
            echo "1.3b: ОШИБКА — не удалось атомарно создать $BBM_ACC_DIR/fs-uuid.txt (путь занят между проверкой и записью или отказ записи); существующий объект НЕ перезаписан"
            G1_STATUS="ОШИБКА"
          fi
        fi
        if [ "$G1_STATUS" = "УСПЕХ" ] && [ ! -e /tmp/bbm-test-fs.uuid ] && [ ! -L /tmp/bbm-test-fs.uuid ]; then
          # атомарное создание эталона (noclobber): существующий НИКОГДА не перезаписывается
          # и не открывается на запись; проверка выше — только диагностика: от гонки
          # защищает атомарный отказ; код возврата проверяется явно
          if ( set -o noclobber; printf '%s\n' "$FS_UUID" > /tmp/bbm-test-fs.uuid ); then
            echo "1.3b: эталон зафиксирован для следующих прогонов (/tmp/bbm-test-fs.uuid, создан атомарно)"
          else
            echo "1.3b: ОШИБКА — не удалось атомарно создать эталон /tmp/bbm-test-fs.uuid (путь занят между проверкой и записью, в том числе символической ссылкой, или отказ записи); существующий объект НЕ перезаписан и НЕ удален"
            G1_STATUS="ОШИБКА"
          fi
        fi
      fi
    fi
  fi
fi

if [ "$G1_STATUS" = "УСПЕХ" ]; then
  # --- 1.4 btrfs subvolume show: ИДЕНТИЧНОСТЬ тестового источника ---
  echo "--- btrfs subvolume show /mnt/btrfs-test/source:"
  if sudo btrfs subvolume show /mnt/btrfs-test/source; then
    echo "1.4: ОК — /mnt/btrfs-test/source является subvolume"
  else
    echo "1.4: /mnt/btrfs-test/source не является subvolume (создайте его в группе 2 и повторите группу 1)"
    G1_STATUS="ПРОПУЩЕНО"
  fi
fi

if [ "$G1_STATUS" = "УСПЕХ" ] || [ "$G1_STATUS" = "ПРОПУЩЕНО" ]; then
  # --- 1.5 источник — НЕ верхний уровень ФС (subvolid 5) ---
  if [ "$G1_STATUS" = "ПРОПУЩЕНО" ]; then
    echo "1.5: ПРОПУЩЕНО — источник еще не создан (группа 2)"
  else
    SRC_ROOTID=$(sudo btrfs inspect-internal rootid /mnt/btrfs-test/source 2>/dev/null)
    if [ -n "$SRC_ROOTID" ]; then
      echo "1.5: subvolid источника: $SRC_ROOTID"
      if [ "$SRC_ROOTID" = "5" ]; then
        echo "1.5: ОШИБКА — источник является ВЕРХНИМ УРОВНЕМ ФС (subvolid=5); тестовый источник обязан быть отдельным subvolume; СТОП"
        G1_STATUS="ОШИБКА"
      else
        echo "1.5: ОК — источник не является верхним уровнем ФС"
      fi
    else
      echo "1.5: ОШИБКА — не удалось определить subvolid источника; СТОП"
      G1_STATUS="ОШИБКА"
    fi
  fi
fi

if [ "$G1_STATUS" != "ОШИБКА" ]; then
  # --- 1.6 btrfs subvolume list: структура subvolume ---
  echo "--- btrfs subvolume list /mnt/btrfs-test:"
  if sudo btrfs subvolume list /mnt/btrfs-test; then
    echo "1.6: ОК — структура subvolume получена (строки вида 'ID 256 gen 39 top level 5 path имя')"
  else
    echo "1.6: ОШИБКА — btrfs subvolume list не выполнен"
    G1_STATUS="ОШИБКА"
  fi
  df -h /mnt/btrfs-test
fi
echo "ГРУППА 1: $G1_STATUS"
```

- **Ожидаемый результат:** 1.0 — создан служебный каталог приемки
  `/tmp/bbm-acceptance.XXXXXX` (права 700) с идентификатором запуска
  `run-id.txt`, записан файл указателя `/tmp/bbm-acceptance.dir` (две
  строки: путь и идентификатор запуска); все служебные файлы созданы
  атомарно (отказ при занятом пути, код возврата проверен); 1.2 — `btrfs` на
  `/mnt/btrfs-test`, источник `/dev/loop0`; 1.3 — UUID получен,
  устройство `/dev/loop0`, `/dev/sda1` отсутствует; 1.3b — заранее
  известный UUID (файл прошлого прогона или ввод оператора) совпал с

  1.5 — subvolid источника НЕ 5; 1.6 — `btrfs subvolume list` успешен.
- **Признаки ошибки:** любое несовпадение выше; в любом выводе
  фигурирует `/dev/sda1` — немедленный СТОП (риск задеть рабочие
  данные); заранее известный UUID недоступен или не совпал — СТОП
  (обнаруженный на /dev/loop0 UUID эталоном не является);
  `/tmp/bbm-acceptance.dir` существует на старте (в том числе как
  висячая символическая ссылка) — предыдущий прогон не завершен,
  ничего не перезаписывается; mktemp или chmod не выполнены —
  испытания останавливаются до создания указателя;
  отказ атомарного создания (путь занят между проверкой и записью —

  `/tmp/bbm-test-fs.uuid` — символическая ссылка или не обычный файл —

- **Способ остановки:** ничего не меняйте сами; испытания просто не

  откажет в удалении (нет указателя — нет доказательства
  принадлежности): каталог приемки разбирается вручную только ПОСЛЕ

- **Очистка временных объектов:** создается только каталог приемки

  `fs-uuid.txt`, файл указателя `/tmp/bbm-acceptance.dir` (две строки:
  путь и идентификатор запуска; создается атомарно — отказ при
  занятом пути) и эталон `/tmp/bbm-test-fs.uuid` (создается один раз —

  перезаписывается); удаляются группой
  13 (эталон сохраняется между прогонами намеренно — для сверки, что
  ФС та же).

**Статус группы 1: УСПЕХ — если создан каталог приемки с идентификатором
запуска (1.0), все проверки 1.2-1.6 дали ОК и заранее известный UUID
подтвержден двумя независимыми запросами; ПРОПУЩЕНО — если источник

## Группа 2. Тестовые данные ВНУТРИ тестового источника

- **Цель:** создать контролируемое содержимое с разными атрибутами
  (права, владелец, время, симлинк, hardlink, разреженный файл, пробел
  в имени, вложенность, кириллица) для последующей сверки.
- **Предварительные условия:** группа 1 — УСПЕХ (или ПРОПУЩЕНО по
  причине «источник не создан» — тогда создается в этой группе).
- **Правила безопасности группы:** источник обязан ОТСУТСТВОВАТЬ либо
  уже являться ожидаемым subvolume; сам путь `/mnt/btrfs-test/source`
  проверяется на символьную ссылку (включая висячую, `-L`) ДО вызова
  `btrfs subvolume show` — subvolume show следует по ссылкам и без
  этой проверки мог бы «подтвердить» источник через ссылку, открыв
  запись по ней (в том числе в чужой каталог); «существует, но не
  subvolume» — стоп без перезаписи; ошибка создания subvolume
  останавливает группу (никаких тестовых файлов); до записи проверяется
  отсутствие ВСЕХ задействованных файлов И каталогов (включая `docs` и
  вложенную папку) — «существует» значит любой объект: файл, каталог,
  символическая ссылка, в том числе висячая; коды возврата всех команд
  создания (mkdir, tee, dd, chmod, chown, ln, touch) проверяются
  явно — при любой ошибке статус УСПЕХ не выставляется;
  существующие данные НЕ перезаписываются ради теста (никаких `>` и
  `tee` поверх имеющихся файлов).

```bash
G2_STATUS="УСПЕХ"
# --- 2.0 источник: ОТСУТСТВУЕТ (создать) либо УЖЕ ожидаемый subvolume ---
# Символьная ссылка проверяется ДО btrfs subvolume show: show следует по
# ссылкам и без этого мог бы «подтвердить» источник через ссылку (в том
# числе на чужой subvolume), открыв группе 2.2 запись по ссылке. Ссылка
# любого вида (обычная или висячая) — останов группы.
if [ -L /mnt/btrfs-test/source ]; then
  echo "2.0: ОШИБКА — /mnt/btrfs-test/source является символической ссылкой (обычной или висячей); по ссылкам тест не следует, запись через ссылку запрещена. Существующие данные НЕ перезаписываю и subvolume поверх НЕ создаю. Пришлите ls -laA"
  G2_STATUS="ОШИБКА"
elif sudo btrfs subvolume show /mnt/btrfs-test/source > /dev/null 2>&1; then
  echo "2.0: OK — source уже является subvolume (ожидаемое состояние; путь проверен на отсутствие символьной ссылки ДО subvolume show)"
elif [ -e /mnt/btrfs-test/source ]; then
  echo "2.0: ОШИБКА — /mnt/btrfs-test/source существует (файл или каталог), но НЕ является subvolume; существующие данные НЕ перезаписываю и subvolume поверх НЕ создаю. Пришлите ls -laA"
  G2_STATUS="ОШИБКА"
else
  echo "2.0: source отсутствует — создаю subvolume (единственная команда группы, меняющая структуру тестовой ФС)"
  if sudo btrfs subvolume create /mnt/btrfs-test/source; then
    if sudo btrfs subvolume show /mnt/btrfs-test/source > /dev/null 2>&1; then
      echo "2.0: OK — subvolume создан и подтвержден (subvolume show)"
    else
      echo "2.0: ОШИБКА — после создания subvolume show не подтверждает источник; группа остановлена, тестовые файлы НЕ создаются"
      G2_STATUS="ОШИБКА"
    fi
  else
    echo "2.0: ОШИБКА — btrfs subvolume create завершился с ошибкой; группа остановлена, тестовые файлы НЕ создаются"
    G2_STATUS="ОШИБКА"
  fi
fi

# --- 2.1 отказ от перезаписи: ВСЕ задействованные файлы И каталоги обязаны ОТСУТСТВОВАТЬ ---
if [ "$G2_STATUS" = "УСПЕХ" ]; then
  for f in "docs" "docs/вложенная папка" "README.txt" \
           "docs/вложенная папка/файл с пробелом.txt" \
           "sparse.bin" "random.bin" "link-to-readme" "hardlink-to-random"; do
    if [ -e "/mnt/btrfs-test/source/$f" ] || [ -L "/mnt/btrfs-test/source/$f" ]; then
      echo "2.1: ОШИБКА — тестовый объект уже существует (файл, каталог или символическая ссылка, включая висячую): source/$f"
      echo "Данные прошлых запусков НЕ перезаписываются. Пришлите список для анализа"
      G2_STATUS="ОШИБКА"
    fi
  done
  if [ "$G2_STATUS" = "УСПЕХ" ]; then
    echo "2.1: OK — ни один тестовый объект не существует (перезапись исключена)"
  fi
fi

# --- 2.2 создание (только внутри /mnt/btrfs-test/source);
#     код возврата КАЖДОЙ команды проверяется: любая ошибка исключает УСПЕХ ---
if [ "$G2_STATUS" = "УСПЕХ" ]; then
  if sudo mkdir /mnt/btrfs-test/source/docs &&
     sudo mkdir "/mnt/btrfs-test/source/docs/вложенная папка" &&
     echo "marker-text-12345" | sudo tee /mnt/btrfs-test/source/README.txt > /dev/null &&
     echo "nested" | sudo tee "/mnt/btrfs-test/source/docs/вложенная папка/файл с пробелом.txt" > /dev/null &&
     sudo dd if=/dev/zero of=/mnt/btrfs-test/source/sparse.bin bs=1M seek=50 count=1 status=none &&
     sudo dd if=/dev/urandom of=/mnt/btrfs-test/source/random.bin bs=1M count=3 status=none &&
     sudo chmod 640 /mnt/btrfs-test/source/README.txt &&
     { sudo chown root:wheel /mnt/btrfs-test/source/README.txt 2>/dev/null ||
       sudo chown root:root /mnt/btrfs-test/source/README.txt; } &&
     sudo ln -s README.txt /mnt/btrfs-test/source/link-to-readme &&
     sudo ln /mnt/btrfs-test/source/random.bin /mnt/btrfs-test/source/hardlink-to-random &&
     sudo touch -d "2026-01-15 10:30:00" /mnt/btrfs-test/source/README.txt
  then
    echo "2.2: OK — все команды создания завершились с кодом 0"
  else
    echo "2.2: ОШИБКА — команда создания завершилась с ошибкой (код возврата см. выше); успех НЕ объявляется. Частично созданные данные НЕ удаляю — пришлите ls -laR /mnt/btrfs-test/source"
    G2_STATUS="ОШИБКА"
  fi
fi

# --- 2.3 контроль ---
if [ "$G2_STATUS" = "УСПЕХ" ]; then
  [ -f /mnt/btrfs-test/source/README.txt ] || { echo "2.3: ОШИБКА — README.txt не создан"; G2_STATUS="ОШИБКА"; }
  [ -f "/mnt/btrfs-test/source/docs/вложенная папка/файл с пробелом.txt" ] || { echo "2.3: ОШИБКА — вложенный файл не создан"; G2_STATUS="ОШИБКА"; }
  [ -f /mnt/btrfs-test/source/sparse.bin ] || { echo "2.3: ОШИБКА — sparse.bin не создан"; G2_STATUS="ОШИБКА"; }
  [ -f /mnt/btrfs-test/source/random.bin ] || { echo "2.3: ОШИБКА — random.bin не создан"; G2_STATUS="ОШИБКА"; }
  [ -L /mnt/btrfs-test/source/link-to-readme ] || { echo "2.3: ОШИБКА — симлинк не создан"; G2_STATUS="ОШИБКА"; }
  [ /mnt/btrfs-test/source/hardlink-to-random -ef /mnt/btrfs-test/source/random.bin ] || { echo "2.3: ОШИБКА — hardlink не создан/не тот inode"; G2_STATUS="ОШИБКА"; }
  ls -laR /mnt/btrfs-test/source
fi
echo "ГРУППА 2: $G2_STATUS"
```

- **Ожидаемый результат:** `ls -laR` показывает все файлы, включая
  вложенный каталог с кириллицей и пробелом, симлинк и hardlink.
- **Признаки ошибки:** «source существует, но не subvolume» —
  перезапись запрещена (пришлите ls -laA); источник — символьная
  ссылка (обычная или висячая) — стоп ДО вызова subvolume show, иначе
  show прошел бы по ссылке и открыл записи путь через неё;
  `btrfs subvolume create`
  завершился ошибкой — группа остановлена, тестовые файлы НЕ
  создаются; «объект уже существует» (в том числе висячая
  символическая ссылка) — сначала разберите прошлые данные вручную;
  ненулевой код возврата любой команды создания
  (mkdir/tee/dd/chmod/chown/ln/touch) — успех НЕ объявляется; отказ
  записи — каталог не на btrfs или нет прав; `ln: failed to create
  hard link` — файловая система не поддерживает hardlink (не должна
  для btrfs — ошибка среды).
- **Способ остановки:** команды группы пишут только файлы внутри
  `/mnt/btrfs-test/source`; остановка Ctrl+C ничего не портит.
- **Очистка временных объектов:** не требуется (данные целевые, в
  тестовом источнике).

**Статус группы: УСПЕХ — если ls -laR показывает все объекты; иначе
ОШИБКА.**

**Что прислать:** вывод `ls -laR`.

## Группа 3. Проверка обнаружения источников программой

- **Цель:** убедиться, что программа обнаруживает источник на реальной
  Btrfs, обозначает устройства и верхний уровень, ошибки обнаружения
  понятны.
- **Предварительные условия:** группы 1-2 — УСПЕХ; программа скопирована
  в `/opt/btrfs-backup-manager`.
- **Команды** (только просмотр, операция не запускается):

```bash
cd /opt/btrfs-backup-manager
sudo python3 main.py tui --config /opt/btrfs-backup-manager/configs/btrfs-test.py
```

Проверьте по шагам (Esc — отмена на каждом экране, выход — `q`):

1. Главный экран — статусы окружения (Btrfs, gpg, gzip/zstd); строки
   «Отправлено на сетевую шару»; строки профиля нет.
2. Пункт `1. Резервное копирование` → Enter → экран выбора разделов:
   должен присутствовать источник `/mnt/btrfs-test/source` с
   обозначением устройства (например `/dev/loop0[/source]`).
3. Нажмите `d` — экран ошибок обнаружения: он должен быть ПУСТ или
   объяснять причины понятным текстом (НЕ строки вида
   `8 top level 5 path ...`).
4. Esc, Esc, `q` — выход. Ничего не создается: без Enter на финальном
   подтверждении операция не стартует.

- **Ожидаемый результат:** источник виден, экран `d` пуст или понятен.
- **Признаки ошибки:** источник не виден, мусорные пути, обрыв TUI —
  все три случая дефект (пришлите точный вывод/фото экрана).
- **Способ остановки:** Esc/Q в TUI — операция не стартует без явного
  подтверждения.
- **Очистка временных объектов:** не требуется.

**Статус группы: УСПЕХ — источник виден и ошибок нет; ОШИБКА — в любом
другом случае.**

**Что прислать:** виден ли источник, что показал экран `d`.

## Группа 4. Резервное копирование (gzip + GPG, программа целиком)

- **Цель:** полный цикл программы на gzip: снапшот → конвейер → проверка
  архива → метаданные. Группа фиксирует, КАКОЙ ИМЕННО архив создан
  текущим запуском (сравнение перечней архивов ДО и ПОСЛЕ — без выбора
  «новейшего» по маске), и записывает его путь для групп 5-8 и 11.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
if [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
  echo "ГРУППА 4: ОШИБКА — сначала выполните группу 1 (каталог приемки не найден)"
elif [ -e "$BBM_ACC_DIR/archives-before.txt" ] || [ -L "$BBM_ACC_DIR/archives-before.txt" ] \
  || [ -e "$BBM_ACC_DIR/archives-after.txt" ] || [ -L "$BBM_ACC_DIR/archives-after.txt" ] \
  || [ -e "$BBM_ACC_DIR/archive-gzip.path" ] || [ -L "$BBM_ACC_DIR/archive-gzip.path" ]; then
  echo "ГРУППА 4: ОШИБКА — служебный файл группы (archives-before.txt / archives-after.txt / archive-gzip.path) уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
else
  ls -1 /mnt/btrfs-test/.snapshots/backup/*.gz.gpg 2>/dev/null | sort > "$BBM_ACC_DIR/archives-before.txt" || : > "$BBM_ACC_DIR/archives-before.txt"
  cd /opt/btrfs-backup-manager
  sudo python3 main.py backup --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  BACKUP_RC=$?
  if [ "$BACKUP_RC" -ne 0 ]; then
    echo "ГРУППА 4: ОШИБКА — backup завершился с кодом $BACKUP_RC (сообщение об успехе быть не должно)"
  else
    ls -1 /mnt/btrfs-test/.snapshots/backup/*.gz.gpg 2>/dev/null | sort > "$BBM_ACC_DIR/archives-after.txt" || : > "$BBM_ACC_DIR/archives-after.txt"
    NEW_ARCHIVES=$(comm -13 "$BBM_ACC_DIR/archives-before.txt" "$BBM_ACC_DIR/archives-after.txt")
    NEW_COUNT=$(printf '%s\n' "$NEW_ARCHIVES" | grep -c . )
    if [ "${NEW_COUNT:-0}" -eq 1 ]; then
      NEW_ARCHIVE=$(printf '%s\n' "$NEW_ARCHIVES" | head -1)
      echo "$NEW_ARCHIVE" > "$BBM_ACC_DIR/archive-gzip.path"
      echo "Архив ТЕКУЩЕГО запуска (новый, отсутствовавший до): $NEW_ARCHIVE"
      echo "ГРУППА 4: УСПЕХ"
    else
      echo "ГРУППА 4: ОШИБКА — новых архивов: ${NEW_COUNT:-0} (ожидался ровно 1). Новые: ${NEW_ARCHIVES:-нет}. Успех НЕ объявляется"
    fi
  fi
fi
```

Программа спросит пароль GPG (скрытый ввод — введите `acceptance-2026`).
Ожидаемые этапы: [1/7] проверка → [2/7] read-only снапшот → [3/7]
конвейер `btrfs send | gzip | gpg` → [4/7] проверка архива (расшифрование
+ gzip -t + SHA-256) → [5/7] сеть отключена (upload-pending) → [6/7]
retention (сеть отключена — пропускается) → [7/7] завершение.

- **Ожидаемый результат:** строка «Резервное копирование завершено», код
  возврата 0, зафиксирован ровно один новый архив.
- **Признаки ошибки:** ненулевой код возврата; новых архивов 0 (архив не
  создан — успех не объявляется) или больше 1 (неоднозначность —
  пришлите вывод); «операция уже выполняется» — другой запуск держит
  блокировку (`/run/lock/bbm-acceptance-test.lock`), дождитесь или
  завершите его.
- **Способ остановки:** Ctrl+C во время работы — программа завершает
  процессы конвейера; незавершенный архив не считается готовым.
- **Очистка временных объектов:** перечни `archives-before/after.txt`
  остаются в каталоге приемки (700) и удаляются группой 13; архив и
  снапшот — целевые результаты теста, НЕ удаляются.

**Статус группы: УСПЕХ — если программа завершилась с кодом 0 И
зафиксирован ровно один новый архив; иначе ОШИБКА (дальше не переходить).**

**Что прислать:** весь вывод до финального статуса группы.

## Группа 5. Проверка результата backup (архив ТЕКУЩЕГО запуска)

- **Цель:** убедиться, что архив, созданный группой 4, проверяем
  программой (`verify`), метаданные на месте, снапшот read-only. Архив
  выбирается ТОЧНО по зафиксированному в группе 4 пути — без `sort |
  tail -1` и wildcard-выбора: старый результат прошлого запуска не может
  выдать себя за новый.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
ARCHIVE=$(cat "$BBM_ACC_DIR/archive-gzip.path" 2>/dev/null)
if [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
  echo "ГРУППА 5: ПРОПУЩЕНО — нет каталога приемки (группа 1 не выполнена)"
elif [ -z "$ARCHIVE" ] || [ ! -f "$ARCHIVE" ]; then
  echo "ГРУППА 5: ПРОПУЩЕНО — архив текущего запуска не зафиксирован (группа 4 без УСПЕХА)"
else
  echo "Архив текущего запуска: $ARCHIVE"
  cd /opt/btrfs-backup-manager
  sudo python3 main.py verify --archive "$ARCHIVE" --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  VERIFY_RC=$?
  SNAP_NAME=$(basename "$ARCHIVE" .gz.gpg)
  SNAP_PATH="/mnt/btrfs-test/.snapshots/${SNAP_NAME}"
  echo "Снапшот текущего запуска: $SNAP_PATH"
  if sudo btrfs subvolume show "$SNAP_PATH" > /dev/null 2>&1; then
    RO_OUT=$(sudo btrfs property get "$SNAP_PATH" ro)
    echo "property get ro: $RO_OUT"
  else
    RO_OUT="ОТСУТСТВУЕТ"
    echo "5.3: ОШИБКА — снапшот текущего запуска не найден: $SNAP_PATH"
  fi
  JSON_OK=no
  if [ -f "${ARCHIVE}.json" ] && grep -q '"sha256"' "${ARCHIVE}.json" && grep -q 'verified' "${ARCHIVE}.json"; then
    JSON_OK=yes
  fi
  echo "5.1 verify: rc=$VERIFY_RC; 5.2 json с sha256/verified: $JSON_OK; 5.3 ro: $RO_OUT"
  if [ "$VERIFY_RC" -eq 0 ] && [ "$JSON_OK" = "yes" ] && [ "$RO_OUT" = "ro=true" ]; then
    echo "ГРУППА 5: УСПЕХ — verify без ошибок, метаданные на месте, снапшот read-only"
  else
    echo "ГРУППА 5: ОШИБКА — хотя бы одна обязательная проверка не пройдена (см. 5.1-5.3); успех НЕ объявляется"
  fi
fi
```

- **Ожидаемый результат:** `verify` завершается с кодом 0 (расшифрование
  + тест сжатого потока + SHA-256); `.json` рядом с архивом содержит
  SHA-256 и статус verified; `btrfs property get` выводит `ro=true`.
- **Признаки ошибки:** `verify` вернул ненулевой код — дефект группы 4
  (поврежденный или неполный архив); снапшот не найден или `ro=false` —
  дефект создания снапшота; JSON отсутствует/без суммы — дефект
  метаданных.
- **Способ остановки:** группа только читает (verify читает архив и
  пишет журнал); остановка безопасна.
- **Очистка временных объектов:** не требуется.

**Статус группы: УСПЕХ / ОШИБКА — печатается последней строкой блока.**

**Что прислать:** вывод всех команд.

## Группа 6. Восстановление из архива программой (в пустой целевой каталог)

- **Цель:** программа восстанавливает архив в subvolume с предсказуемым
  именем; результат создан ИМЕННО текущей операцией; содержимое и
  АТРИБУТЫ совпадают с источником: файлы, каталоги, права, владельцы,
  временные метки, симлинки, hardlink (inode identity), разреженный
  файл, кириллица и пробелы в именах.
- **Предварительные условия:** группа 5 — УСПЕХ.
- **Правила безопасности группы:** целевой каталог обязан
  ОТСУТСТВОВАТЬ (пустой существующий каталог, файл или символическая
  ссылка на его месте — ОШИБКА: существующее не переиспользуется и не
  удаляется); существующие объекты НЕ удаляются ради теста — при их
  наличии группа завершается ОШИБКОЙ, и данные сохраняются.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
ARCHIVE=$(cat "$BBM_ACC_DIR/archive-gzip.path" 2>/dev/null)
RESTORE_TARGET=/mnt/btrfs-test/restore-target
EXPECTED="$RESTORE_TARGET/$(basename "$ARCHIVE" .gz.gpg)"
if [ -z "$BBM_ACC_DIR" ] || [ -z "$ARCHIVE" ] || [ ! -f "$ARCHIVE" ]; then
  echo "ГРУППА 6: ПРОПУЩЕНО — архив текущего запуска не зафиксирован (группа 4 без УСПЕХА)"
elif [ -e "$RESTORE_TARGET" ] || [ -L "$RESTORE_TARGET" ]; then
  echo "ГРУППА 6: ОШИБКА — целевой каталог $RESTORE_TARGET уже существует (в том числе ПУСТОЙ каталог, файл или символическая ссылка):"
  ls -laA "$RESTORE_TARGET" 2>/dev/null
  echo "Существующие данные НЕ удаляются и НЕ переиспользуются ради теста. Пришлите список для анализа"
elif [ -e "$EXPECTED" ] || [ -L "$EXPECTED" ]; then
  echo "ГРУППА 6: ОШИБКА — объект $EXPECTED уже существует; повторное восстановление поверх запрещено"
elif [ -e "$BBM_ACC_DIR/restored-gzip.path" ] || [ -L "$BBM_ACC_DIR/restored-gzip.path" ]; then
  echo "ГРУППА 6: ОШИБКА — $BBM_ACC_DIR/restored-gzip.path уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
else
  sudo mkdir "$RESTORE_TARGET"
  cd /opt/btrfs-backup-manager
  sudo python3 main.py restore --archive "$ARCHIVE" --target "$RESTORE_TARGET" --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  RESTORE_RC=$?
  if [ "$RESTORE_RC" -ne 0 ]; then
    echo "ГРУППА 6: ОШИБКА — восстановление завершилось с кодом $RESTORE_RC; успех НЕ объявляется"
    echo "Если программа сообщила о частичном результате — НЕ удаляйте его до анализа"
  elif ! sudo btrfs subvolume show "$EXPECTED" > /dev/null 2>&1; then
    echo "ГРУППА 6: ОШИБКА — код возврата 0, но subvolume $EXPECTED не создан"
  else
    echo "--- 6.4 ПОЛНОЕ СРАВНЕНИЕ (содержимое + атрибуты + inode identity) ---"
    sudo bash -c '
    set -u
    SRC="$1"; DST="$2"
    FAIL=0
    # (1) содержимое: файлы, каталоги, симлинки (без разыменования)
    if ! diff -r --no-dereference "$SRC" "$DST"; then
      echo "6.4: РАСХОЖДЕНИЕ содержимого (diff -r)"; FAIL=1
    fi
    # (2) права, владелец, временная метка каждого файла/каталога
    ATTR_SRC=$(cd "$SRC" && find . \( -type f -o -type d \) -exec stat -c "%n %a %U %G %Y" {} + | sort)
    ATTR_DST=$(cd "$DST" && find . \( -type f -o -type d \) -exec stat -c "%n %a %U %G %Y" {} + | sort)
    if [ "$ATTR_SRC" != "$ATTR_DST" ]; then
      echo "6.4: РАСХОЖДЕНИЕ атрибутов (права/владелец/время):"
      diff <(echo "$ATTR_SRC") <(echo "$ATTR_DST") | head -20; FAIL=1
    fi
    # (3) симлинки: цель и факт наличия
    for l in $(cd "$SRC" && find . -type l | sed "s|^\./||"); do
      if [ "$(readlink "$SRC/$l")" != "$(readlink "$DST/$l")" ]; then
        echo "6.4: РАСХОЖДЕНИЕ симлинка: $l"; FAIL=1
      fi
    done
    # (4) hardlink: inode identity, а не только наличие двух имен
    if ! [ "$DST/hardlink-to-random" -ef "$DST/random.bin" ]; then
      echo "6.4: РАСХОЖДЕНИЕ hardlink — имена есть, но это РАЗНЫЕ inode"; FAIL=1
    fi
    # (5) разреженный файл занимает сопоставимый объем
    DU_SRC=$(du -h "$SRC/sparse.bin" | cut -f1); DU_DST=$(du -h "$DST/sparse.bin" | cut -f1)
    echo "6.4: sparse: источник $DU_SRC, восстановленный $DU_DST (ожидается ~1 МиБ у обоих)"
    # (6) кириллица и пробелы в именах
    [ -f "$DST/docs/вложенная папка/файл с пробелом.txt" ] || { echo "6.4: РАСХОЖДЕНИЕ — вложенный файл с кириллицей/пробелом не найден"; FAIL=1; }
    exit $FAIL
    ' compare "$(/bin/ls -d /mnt/btrfs-test/source)" "$EXPECTED"
    CMP_RC=$?
    if [ "$CMP_RC" -eq 0 ]; then
      echo "$EXPECTED" > "$BBM_ACC_DIR/restored-gzip.path"
      echo "ГРУППА 6: УСПЕХ — subvolume восстановлен; содержимое, атрибуты, hardlink (inode) и sparse совпадают: $EXPECTED"
    else
      echo "ГРУППА 6: ОШИБКА — см. 6.4 выше; успех НЕ объявляется"
    fi
  fi
fi
```

Пароль тот же (`acceptance-2026`). Программа ДО `btrfs receive` проверит

- **Ожидаемый результат:** код возврата 0, `btrfs subvolume show`

- **Признаки ошибки:** ненулевой код; «subvolume ... уже существует»

- **Способ остановки:** отказ программы ДО receive оставляет целевой

**Статус группы: УСПЕХ / ОШИБКА / ПРОПУЩЕНО — печатается последней
строкой блока.**

**Что прислать:** вывод программы, сравнение 6.4, итоговую строку.

## Группа 7. Атрибуты восстановленного и проверка сжатия/шифрования

- **Цель:** (а) наглядно показать совпадение атрибутов источника и
  восстановленного; (б) зашифрованный архив корректен КАК gzip-поток
  ПОСЛЕ расшифрования: сначала расшифрование в защищенный временный файл
  (600, каталог приемки 700), затем `gzip -t` на расшифрованном файле,
  затем удаление. `gzip -t` на зашифрованном `.gpg` НЕ выполняется
  (это бессмысленно и всегда дало бы ошибку). Коды возврата gpg и gzip
  проверяются явно, без `|| true`.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
ARCHIVE=$(cat "$BBM_ACC_DIR/archive-gzip.path" 2>/dev/null)
RESTORED=$(cat "$BBM_ACC_DIR/restored-gzip.path" 2>/dev/null)
if [ -z "$RESTORED" ] || [ ! -d "$RESTORED" ] || [ -z "$ARCHIVE" ]; then
  echo "ГРУППА 7: ПРОПУЩЕНО — результат группы 6 не зафиксирован"
elif [ -e "$BBM_ACC_DIR/decrypted-current.gz" ] || [ -L "$BBM_ACC_DIR/decrypted-current.gz" ]; then
  echo "ГРУППА 7: ОШИБКА — $BBM_ACC_DIR/decrypted-current.gz уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
else
  echo "7.а Атрибуты восстановленного subvolume: $RESTORED"
  sudo stat -c '%a %U:%G %n %y' /mnt/btrfs-test/source/README.txt "$RESTORED/README.txt"
  sudo ls -la "$RESTORED" | grep -E "link-to-readme|hardlink" || echo "7.а: ОШИБКА — симлинк/hardlink не найдены"
  sudo du -h /mnt/btrfs-test/source/sparse.bin "$RESTORED/sparse.bin"
  echo "7.б Проверка сжатия: расшифрование в защищенный временный файл, затем gzip -t"
  read -rsp "Пароль GPG архива: " ACCPASS; echo
  TMP_DECRYPT="$BBM_ACC_DIR/decrypted-current.gz"   # отсутствие проверено выше (включая висячие симлинки)
  umask 077
  gpg --batch --quiet --pinentry-mode loopback --passphrase-fd 0 -o "$TMP_DECRYPT" --decrypt "$ARCHIVE" <<< "$ACCPASS"
  GPG_RC=$?
  if [ "$GPG_RC" -ne 0 ]; then
    echo "7.б: ОШИБКА — расшифрование не удалось (gpg rc=$GPG_RC: неверный пароль или поврежденный архив)"
    rm -f "$TMP_DECRYPT"
    echo "ГРУППА 7: ОШИБКА"
  else
    chmod 600 "$TMP_DECRYPT"
    gzip -t "$TMP_DECRYPT"
    GZIP_RC=$?
    rm -f "$TMP_DECRYPT"
    echo "7.б: gpg rc=$GPG_RC; gzip -t rc=$GZIP_RC (0 = поток цел)"
    if [ "$GZIP_RC" -eq 0 ]; then
      echo "ГРУППА 7: УСПЕХ — расшифрованный поток текущего запуска прошел gzip -t"
    else
      echo "ГРУППА 7: ОШИБКА — сжатый поток поврежден (gzip -t rc=$GZIP_RC)"
    fi
  fi
  unset ACCPASS
fi
```

- **Ожидаемый результат:** `stat` — права `640`, владелец root, время
  2026-01-15 10:30 у обоих файлов; симлинк и hardlink на месте;
  `du` разреженного файла ~1 МиБ (не 50) у обоих; gpg rc=0 и gzip -t
  rc=0; временный расшифрованный файл удален в обеих ветках.
- **Признаки ошибки:** расхождение атрибутов; `gpg: расшифрование не
  удалось` — неверный пароль (повторите с паролем группы 4);
  `gzip: ... invalid` — поток поврежден (дефект). Пароль не сохраняется
  в файлы и не попадает в argv (`--passphrase-fd 0`, переменная очищается
  `unset`).
- **Способ остановки:** чтение атрибутов безопасно; ветка расшифрования
  пишет только во временный файл каталога приемки.
- **Очистка временных объектов:** расшифрованный файл
  `$BBM_ACC_DIR/decrypted-current.gz` (600) удаляется сразу после
  `gzip -t` — и при успехе, и при ошибке расшифрования.

**Статус группы: УСПЕХ — совпали все атрибуты И обе проверки конвейера
(gpg rc=0, gzip -t rc=0); иначе ОШИБКА; ПРОПУЩЕНО — если группа 6 не
завершилась УСПЕХОМ.**

**Что прислать:** весь вывод.

## Группа 8. Системный конвейер БЕЗ шифрования (gzip и zstd) — btrfs send → btrfs receive

- **Цель:** проверить пары «сжатие × без шифрования» ПРЯМЫМИ командами
  btrfs на настоящей Btrfs: `btrfs send → сжатие → распаковка →
  btrfs receive`. Источник send — снапшот ТЕКУЩЕГО запуска (имя выводится
  из зафиксированного группой 4 пути архива, БЕЗ выбора «новейшего» по
  маске). Ошибка любой стадии останавливает блок и не маскируется:
  `set -euo pipefail` внутри `sudo bash -c`, коды стадий печатаются из
  `PIPESTATUS`. Существование ЛЮБОГО из четырех объектов raw-* (в том
  числе ПУСТОГО каталога raw-*-restore или символической ссылки,
  включая висячую) останавливает группу до конвейеров. Манифест
  объектов текущего запуска: каталоги raw-*-restore заносятся в
  манифест ПОСЛЕ успешного создания (запись доказывает, что каталог
  создан текущим запуском), файлы потоков raw-*.bstream — ДО
  конвейера (частичный поток при отказе конвейера подлежит очистке
  группой 9). Группа 9 удаляет объекты ТОЛЬКО по манифесту текущего
  запуска.
- **Предварительные условия:** группа 4 — УСПЕХ (зафиксирован архив
  текущего запуска). Проверка `zstd --version` определяет статус ветки
  zstd (ПРОПУЩЕНО при отсутствии утилиты).

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
ARCHIVE=$(cat "$BBM_ACC_DIR/archive-gzip.path" 2>/dev/null)
if [ -z "$ARCHIVE" ]; then
  echo "ГРУППА 8: ПРОПУЩЕНО — архив текущего запуска не зафиксирован (группа 4 без УСПЕХА)"
else
  SNAP="/mnt/btrfs-test/.snapshots/$(basename "$ARCHIVE" .gz.gpg)"
  echo "Источник send (снапшот текущего запуска): $SNAP"
  G8="OK"
  # следы прошлых запусков: перезапись и удаление запрещены — стоп группы.
  # «Существует» = любой объект: файл, каталог (ДАЖЕ ПУСТОЙ), символическая ссылка (включая висячую)
  for f in /mnt/btrfs-test/raw-gzip.bstream /mnt/btrfs-test/raw-zstd.bstream; do
    if [ -e "$f" ] || [ -L "$f" ]; then
      echo "8: ОШИБКА — $f уже существует (файл, каталог или символическая ссылка; прошлый запуск); НЕ перезаписываю"
      G8="STOP"
    fi
  done
  for d in /mnt/btrfs-test/raw-gzip-restore /mnt/btrfs-test/raw-zstd-restore; do
    if [ -e "$d" ] || [ -L "$d" ]; then
      echo "8: ОШИБКА — $d уже существует (в том числе ПУСТОЙ каталог, файл или символическая ссылка; прошлый запуск); НЕ перезаписываю и НЕ переиспользую: группа 9 удаляет только созданное текущим запуском"
      G8="STOP"
    fi
  done
  # манифест: символическая ссылка на его месте или не-файл — стоп (по ссылкам не следую)
  if [ -L "$BBM_ACC_DIR/raw-manifest.txt" ]; then

      echo "ГРУППА 8 (gzip): ОШИБКА — gzip-поток не цел"; exit 1; }

    RECEIVED="/mnt/btrfs-test/raw-gzip-restore/$(basename "$SNAP")"
    btrfs subvolume show "$RECEIVED" > /dev/null || {
      echo "ГРУППА 8 (gzip): ОШИБКА — результат receive не обнаружен: $RECEIVED"; exit 1; }

Комбинации С шифрованием: gzip — группы 4-7, zstd — группа 10.

- **Ожидаемый результат:** оба конвейера завершаются `УСПЕХ`; `diff`
  без расхождений; полученный subvolume носит имя снапшота (см. строку
  «Источник send»); каталоги raw-*-restore созданы на проверенно
  свободном месте и занесены в манифест после создания; файлы потоков
  занесены в манифест до конвейера.
- **Признаки ошибки:** `btrfs send: ... not read-only` — выбран не
  снапшот; отказ receive (проверьте свободное место: `df -h
  /mnt/btrfs-test`); расхождение diff — дефект конвейера; любой
  существующий raw-* объект (в том числе ПУСТОЙ каталог или
  символическая ссылка, включая висячую) — СТОП без перезаписи и без
  удаления. Блок останавливается на ПЕРВОЙ ошибке с кодами стадий —
  успех следующей стадии не маскирует отказ предыдущей.
- **Способ остановки:** блоки работают только с объектами
  `/mnt/btrfs-test/raw-*`, отсутствовавшими на момент стартовой
  проверки (пустой существующий каталог — тоже стоп) и созданными
  этими же блоками; снапшот и архивы только читаются. Ctrl+C
  останавливает конвейер; частичные файлы удаляются группой 9 по
  манифесту.
- **Очистка временных объектов:** создаются только объекты
  `/mnt/btrfs-test/raw-*`; каталоги заносятся в манифест ПОСЛЕ
  успешного создания (запись доказывает создание текущим запуском),
  файлы потоков — ДО конвейера (частичный поток при отказе будет
  удален группой 9); удаляет их группа 9 строго по манифесту текущего
  запуска.

**Статус группы: gzip — УСПЕХ/ОШИБКА; zstd — УСПЕХ/ОШИБКА/ПРОПУЩЕНО
(печатается в конце каждого блока).**

## Группа 9. Очистка проверочного конвейера (только созданного группой 8)

- **Цель:** удалить ТОЛЬКО объекты, созданные группой 8 ТЕКУЩЕГО
  запуска — по манифесту текущего запуска. Удалению предшествует
  ПОЛНАЯ предварительная проверка: сначала — сам каталог приемки (не
  символьная ссылка, включая висячую; существующий каталог; realpath
  соответствует шаблону /tmp/bbm-acceptance.XXXXXX), затем — служебные
  файлы (указатель, run-id.txt, манифест — обычные файлы, НЕ
  символические ссылки; идентификатор запуска в указателе (вторая
  строка) совпадает с run-id.txt), затем — ЦЕЛИКОМ весь манифест:
  каждая запись сверяется с четырьмя разрешенными именами группы 8,
  существующие объекты — на допустимый тип и отсутствие символических
  ссылок (в том числе внутри каталогов восстановления), каталоги
  восстановления — на ожидаемую структуру: пустой ЛИБО ровно один
  received subvolume с именем снапшота текущего запуска (имя выводится
  из зафиксированного группой 4 архива) и подтверждением `btrfs
  subvolume show`. Любая ошибка или неоднозначность ЛЮБОЙ записи —
  останов группы БЕЗ ЕДИНОГО удаления: сначала проверяется всё, и
  только потом удаляется (частичная очистка исключена — недопустимая
  вторая запись не приводит к удалению по первой). Удаление принятого
  (read-only, received) subvolume выполняется НАПРЯМУЮ `btrfs
  subvolume delete` — без предварительной смены свойства ro.
- **Предварительные условия:** группа 8 выполнена (успех или
  остановка). Нет манифеста — группа 8 не создавала объектов: удалять
  нечего (ПРОПУЩЕНО), ничего не удаляется — но только при исправных
  каталоге приемки и служебных файлах; при непрохождении любой их
  проверки (ссылка, не-файл, не-каталог, realpath вне шаблона,

    exit 1

    echo "ГРУППА 9: ОТКАЗ — $MANIFEST существует, но не является обычным файлом; ничего не удаляю"

    echo "ГРУППА 9: ПРОПУЩЕНО — группа 8 не создавала объектов (манифест отсутствует); ничего не удаляю"
    exit 0

        fi
        ENTRY_COUNT=0
        if [ -n "$LS_OUT" ]; then ENTRY_COUNT=$(wc -l <<< "$LS_OUT"); fi
        if [ "$ENTRY_COUNT" -gt 1 ]; then
          echo "ГРУППА 9: ОТКАЗ — в $path объектов: $ENTRY_COUNT, ожидается 1 (пустой каталог или received subvolume). Не удаляю вслепую; ничего не удалено; пришлите ls -laA $path"
          exit 1
        fi
        if [ "$ENTRY_COUNT" -eq 0 ]; then
          continue
        fi
        ENTRY="$LS_OUT"
        if [ -L "$path/$ENTRY" ]; then
          echo "ГРУППА 9: ОТКАЗ — $path/$ENTRY является символической ссылкой (в том числе висячей); ничего не удалено"
          exit 1
        fi
        if [ ! -d "$path/$ENTRY" ]; then
          echo "ГРУППА 9: ОТКАЗ — $path/$ENTRY не является каталогом (ожидался received subvolume); ничего не удалено"
          exit 1
        fi
        # ожидаемое имя выводится один раз — из archive-gzip.path текущего запуска
        if [ "$EXPECTED_READY" != "yes" ]; then
          if [ -L "$ACC/archive-gzip.path" ]; then
            echo "ГРУППА 9: ОТКАЗ — $ACC/archive-gzip.path является символической ссылкой; ожидаемое имя received subvolume недоказуемо; ничего не удалено"
            exit 1
          fi
          if [ ! -f "$ACC/archive-gzip.path" ]; then
            echo "ГРУППА 9: ОТКАЗ — $ACC/archive-gzip.path отсутствует или не обычный файл: ожидаемое имя received subvolume недоказуемо (группа 8 выполняется только после УСПЕХА группы 4); ничего не удалено"
            exit 1
          fi
          ACC_ARCHIVE=$(sed -n 1p "$ACC/archive-gzip.path") || {
            echo "ГРУППА 9: ОТКАЗ — не удалось прочитать $ACC/archive-gzip.path; ничего не удалено"
            exit 1
          }
          EXPECTED_NAME=$(basename "$ACC_ARCHIVE" .gz.gpg)
          if [ -z "$EXPECTED_NAME" ]; then
            echo "ГРУППА 9: ОТКАЗ — в $ACC/archive-gzip.path нет пути архива: ожидаемое имя received subvolume недоказуемо; ничего не удалено"
            exit 1
          fi
          EXPECTED_READY="yes"
        fi
        if [ "$ENTRY" != "$EXPECTED_NAME" ]; then
          echo "ГРУППА 9: ОТКАЗ — объект в $path называется «$ENTRY», ожидался received subvolume «$EXPECTED_NAME» (имя снапшота текущего запуска); ничего не удалено"
          exit 1
        fi
        if ! btrfs subvolume show "$path/$ENTRY" > /dev/null 2>&1; then
          echo "ГРУППА 9: ОТКАЗ — $path/$ENTRY не является subvolume (ожидался received subvolume группы 8); ничего не удалено"
          exit 1
        fi ;;
    esac
  done <<< "$MANIFEST_CONTENT"
  # --- ЭТАП 6. Очистка — ТОЛЬКО после успешной полной предварительной
  #     проверки, по той же прочитанной копии манифеста; состояние каждого
  #     объекта перепроверяется перед удалением (могло измениться после ЭТАПА 5) ---
  while IFS= read -r path || [ -n "$path" ]; do
    [ -n "$path" ] || continue
    if [ -L "$path" ]; then
      echo "ГРУППА 9: ОТКАЗ — после предварительной проверки $path стал символической ссылкой; этот объект НЕ удаляю (о ранее удаленных объектах см. строки выше)"
      exit 1
    fi
    if [ ! -e "$path" ]; then
      echo "$path: ПРОПУЩЕНО (уже отсутствует)"
      continue
    fi
    case "$path" in
      *.bstream)
        if ! rm -f "$path"; then
          echo "ГРУППА 9: ОШИБКА — не удалось удалить $path"
          exit 1
        fi
        echo "$path: удален (УСПЕХ)" ;;
      *-restore)
        if ! LS_OUT=$(ls -1A "$path"); then
          echo "ГРУППА 9: ОШИБКА — не удалось перечислить содержимое $path"
          exit 1
        fi
        ENTRY_COUNT=0
        if [ -n "$LS_OUT" ]; then ENTRY_COUNT=$(wc -l <<< "$LS_OUT"); fi
        if [ "$ENTRY_COUNT" -eq 0 ]; then
          if ! rm -rf "$path"; then
            echo "ГРУППА 9: ОШИБКА — не удалось удалить $path"
            exit 1
          fi
          echo "$path: удален (пустой каталог, созданный группой 8 текущего запуска)"
        else
          ENTRY="$LS_OUT"
          if [ "$ENTRY_COUNT" -ne 1 ] || [ "$ENTRY" != "$EXPECTED_NAME" ] || [ -L "$path/$ENTRY" ] || [ ! -d "$path/$ENTRY" ]; then
            echo "ГРУППА 9: ОТКАЗ — после предварительной проверки состояние $path изменилось (объектов: $ENTRY_COUNT); этот объект НЕ удаляю"
            exit 1
          fi
          if ! btrfs subvolume delete "$path/$ENTRY"; then
            echo "ГРУППА 9: ОШИБКА — btrfs subvolume delete отказал для $path/$ENTRY (пришлите вывод)"
            exit 1
          fi
          if ! rm -rf "$path"; then
            echo "ГРУППА 9: ОШИБКА — не удалось удалить каталог $path"
            exit 1
          fi
          echo "$path/$ENTRY: удален (УСПЕХ)"
        fi ;;
    esac
  done <<< "$MANIFEST_CONTENT"
  echo "ГРУППА 9: УСПЕХ — полная предварительная проверка манифеста пройдена; объекты группы 8 (по манифесту текущего запуска) удалены или помечены ПРОПУЩЕНО"
  ' cleanup "$BBM_ACC_DIR" || echo "ГРУППА 9: ОШИБКА — см. сообщение выше"
fi
```

- **Ожидаемый результат:** каталог приемки и служебные файлы прошли
  проверку (каталог — не ссылка, realpath соответствует шаблону;
  указатель — обычный файл ровно из двух строк; идентификатор запуска
  совпадает с run-id.txt); полная предварительная проверка ВСЕГО
  манифеста пройдена до первого удаления; каждый объект удален или
  честно помечен ПРОПУЩЕНО; снапшот группы 4, архивы и восстановленный
  группой 6 subvolume НЕ затрагиваются.
- **Признаки ошибки:** каталог приемки — символьная ссылка (включая
  висячую), не существующий каталог или realpath вне шаблона
  /tmp/bbm-acceptance.XXXXXX — ОТКАЗ; несовпадение или отсутствие
  идентификатора запуска (указатель ↔ run-id.txt) — ОТКАЗ ДО любого
  удаления; указатель, run-id.txt или манифест — символьная ссылка или
  не обычный файл — ОТКАЗ; путь не соответствует именам группы 8 —
  ОТКАЗ (даже если недопустимая запись в конце манифеста: все записи
  проверяются до первого удаления); символьная ссылка на месте объекта
  манифеста, манифеста или ВНУТРИ каталога восстановления — ОТКАЗ;
  не-файл/не-каталог на месте объекта манифеста — ОТКАЗ; в каталоге
  восстановления больше одного объекта, объект с неожидаемым именем
  или не subvolume — ОТКАЗ (не удаляю вслепую); изменение состояния
  объекта после предварительной проверки — ОТКАЗ для этого объекта;
  `subvolume delete` отказал — пришлите вывод.
- **Способ остановки:** перед любым удалением проверяются каталог
  приемки, служебные файлы и ВЕСЬ манифест (каждая запись: имена,
  типы, отсутствие ссылок, структура каталогов восстановления);
  удаление выполняется только по полностью проверенному манифесту
  текущего запуска (каталоги — запись после создания, файлы потоков —
  до конвейера), по той же прочитанной копии манифеста, с
  перепроверкой состояния каждого объекта перед удалением; любой
  другой объект не затрагивается.
- **Очистка временных объектов:** сама группа и есть очистка объектов
  группы 8; манифест остается в каталоге приемки и удаляется группой 13
  вместе с ним.

**Статус группы: УСПЕХ — полная предварительная проверка пройдена, все
строки «удален»/«ПРОПУЩЕНО» и нет сообщений об остановке; ОТКАЗ/ОШИБКА —
если есть сообщение об остановке или отказе (отказ до этапа очистки
означает: не удален ни один объект; останов на этапе очистки возможен
только при изменении состояния объекта после проверки — об этом
сообщается отдельно).**

**Что прислать:** вывод блока.

## Группа 10. Резервное копирование и проверка с zstd (программа)

- **Цель:** полный цикл программы на zstd (с шифрованием) — отдельный
  файл настроек `btrfs-test-zstd.py`; алгоритм не подменяется. Дополнительно —
  проверка формата: расшифрование в защищенный временный файл и `zstd -t`
  на нем. Архив выбирается по разности перечней ДО/ПОСЛЕ — как в группе 4.
- **Предварительные условия:** группа 4 — УСПЕХ; zstd установлен
  (иначе ПРОПУЩЕНО).

```bash
if ! command -v zstd > /dev/null 2>&1; then
  echo "ГРУППА 10: ПРОПУЩЕНО — zstd не установлен"
else
  BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
  if [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
    echo "ГРУППА 10: ПРОПУЩЕНО — нет каталога приемки (группа 1 не выполнена)"
  elif [ -e "$BBM_ACC_DIR/zstd-before.txt" ] || [ -L "$BBM_ACC_DIR/zstd-before.txt" ] \
    || [ -e "$BBM_ACC_DIR/zstd-after.txt" ] || [ -L "$BBM_ACC_DIR/zstd-after.txt" ] \
    || [ -e "$BBM_ACC_DIR/decrypted-current.zst" ] || [ -L "$BBM_ACC_DIR/decrypted-current.zst" ]; then
    echo "ГРУППА 10: ОШИБКА — служебный файл группы (zstd-before.txt / zstd-after.txt / decrypted-current.zst) уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
  else
    ls -1 /mnt/btrfs-test/.snapshots/backup/*.zst.gpg 2>/dev/null | sort > "$BBM_ACC_DIR/zstd-before.txt" || : > "$BBM_ACC_DIR/zstd-before.txt"
    cd /opt/btrfs-backup-manager
    sudo python3 main.py backup --config /opt/btrfs-backup-manager/configs/btrfs-test-zstd.py
    Z_BACKUP_RC=$?
    if [ "$Z_BACKUP_RC" -ne 0 ]; then
      echo "ГРУППА 10: ОШИБКА — backup (zstd) завершился с кодом $Z_BACKUP_RC"
    else
      ls -1 /mnt/btrfs-test/.snapshots/backup/*.zst.gpg 2>/dev/null | sort > "$BBM_ACC_DIR/zstd-after.txt" || : > "$BBM_ACC_DIR/zstd-after.txt"
      NEW_Z=$(comm -13 "$BBM_ACC_DIR/zstd-before.txt" "$BBM_ACC_DIR/zstd-after.txt")
      NEW_Z_COUNT=$(printf '%s\n' "$NEW_Z" | grep -c . )
      if [ "${NEW_Z_COUNT:-0}" -ne 1 ]; then
        echo "ГРУППА 10: ОШИБКА — новых zstd-архивов: ${NEW_Z_COUNT:-0} (ожидался 1); успех НЕ объявляется"
      else
        Z_ARCHIVE=$(printf '%s\n' "$NEW_Z" | head -1)
        echo "Архив текущего запуска (zstd): $Z_ARCHIVE"
        sudo python3 main.py verify --archive "$Z_ARCHIVE" --config /opt/btrfs-backup-manager/configs/btrfs-test-zstd.py
        Z_VERIFY_RC=$?
        echo "10.1 backup: rc=$Z_BACKUP_RC; 10.2 verify: rc=$Z_VERIFY_RC"
        if [ "$Z_VERIFY_RC" -ne 0 ]; then
          echo "ГРУППА 10: ОШИБКА — verify (zstd) не пройден; успех НЕ объявляется"
        else
          read -rsp "Пароль GPG архива: " ACCPASS; echo
          TMP_Z="$BBM_ACC_DIR/decrypted-current.zst"   # отсутствие проверено выше (включая висячие симлинки)
          umask 077
          gpg --batch --quiet --pinentry-mode loopback --passphrase-fd 0 -o "$TMP_Z" --decrypt "$Z_ARCHIVE" <<< "$ACCPASS"
          Z_GPG_RC=$?
          if [ "$Z_GPG_RC" -ne 0 ]; then
            echo "10.3: ОШИБКА — расшифрование (gpg rc=$Z_GPG_RC)"
            rm -f "$TMP_Z"
            echo "ГРУППА 10: ОШИБКА"
          else
            chmod 600 "$TMP_Z"
            zstd -t -q "$TMP_Z"
            Z_TEST_RC=$?
            rm -f "$TMP_Z"
            echo "10.3 формат zstd (расшифрованный файл): gpg rc=$Z_GPG_RC, zstd -t rc=$Z_TEST_RC"
            if [ "$Z_TEST_RC" -eq 0 ]; then
              echo "ГРУППА 10: УСПЕХ — backup и verify на zstd прошли, формат потока подтвержден"
            else
              echo "ГРУППА 10: ОШИБКА — zstd-поток поврежден"
            fi
          fi
          unset ACCPASS
        fi
      fi
    fi
  fi
fi
```

Пароль тот же (`acceptance-2026`).

- **Ожидаемый результат:** «Резервное копирование завершено» (конвейер
  `btrfs send | zstd | gpg`), verify без ошибок, расшифрованный поток
  проходит `zstd -t`.
- **Признаки ошибки:** ненулевой код backup/verify; новых zstd-архивов не
  ровно 1; gpg или zstd -t вернули ошибку. Все они — ОШИБКА (успех не
  объявляется).
- **Способ остановки:** как в группе 4.
- **Очистка временных объектов:** перечни и расшифрованный файл — в
  каталоге приемки (700/600), временный файл удаляется сразу в обеих
  ветках; группа 13 удаляет перечни.

**Статус группы: УСПЕХ / ОШИБКА / ПРОПУЩЕНО — печатается в блоке.**

**Что прислать:** вывод блока.

## Группа 11. Поведение при ошибке (безопасно для данных)

- **Цель:** программа обязана ОТКАЗЫВАТЬСЯ при неверном пароле и
  поврежденном архиве (не выдавать успех), оригинал не повреждается.
  Коды возврата проверяются явно; повреждается КОПИЯ в каталоге приемки,
  не оригинал.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
ARCHIVE=$(cat "$BBM_ACC_DIR/archive-gzip.path" 2>/dev/null)
if [ -z "$ARCHIVE" ] || [ ! -f "$ARCHIVE" ]; then
  echo "ГРУППА 11: ПРОПУЩЕНО — архив текущего запуска не зафиксирован"
elif [ -e "$BBM_ACC_DIR/damaged-copy.gz.gpg" ] || [ -L "$BBM_ACC_DIR/damaged-copy.gz.gpg" ]; then
  echo "ГРУППА 11: ОШИБКА — $BBM_ACC_DIR/damaged-copy.gz.gpg уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
else
  echo "Архив для проверок: $ARCHIVE"
  echo "--- 11.1: неверный пароль (на запрос введите wrong-pass) — ожидаем отказ"
  cd /opt/btrfs-backup-manager
  sudo python3 main.py verify --archive "$ARCHIVE" --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  RC11_1=$?
  echo "код возврата 11.1: $RC11_1 (должен быть НЕ 0, сообщение о неверном пароле)"
  echo "--- 11.2: поврежденный архив — портится КОПИЯ в каталоге приемки (не оригинал)"
  cp "$ARCHIVE" "$BBM_ACC_DIR/damaged-copy.gz.gpg"
  printf 'X' | sudo dd of="$BBM_ACC_DIR/damaged-copy.gz.gpg" bs=1 seek=1000 conv=notrunc status=none
  sudo python3 main.py verify --archive "$BBM_ACC_DIR/damaged-copy.gz.gpg" --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  RC11_2=$?
  echo "код возврата 11.2: $RC11_2 (должен быть НЕ 0, сообщение о повреждении)"
  rm -f "$BBM_ACC_DIR/damaged-copy.gz.gpg"
  echo "--- 11.3: оригинал цел — проверка с ПРАВИЛЬНЫМ паролем (acceptance-2026)"
  sudo python3 main.py verify --archive "$ARCHIVE" --config /opt/btrfs-backup-manager/configs/btrfs-test.py
  RC11_3=$?
  echo "код возврата 11.3: $RC11_3 (должен быть 0)"
  if [ "$RC11_1" -ne 0 ] && [ "$RC11_2" -ne 0 ] && [ "$RC11_3" -eq 0 ]; then
    echo "ГРУППА 11: УСПЕХ — 11.1 и 11.2 отказали, 11.3 прошел, оригинал цел"
  else
    echo "ГРУППА 11: ОШИБКА — успех на испорченных данных (11.1=$RC11_1, 11.2=$RC11_2) или повреждение оригинала (11.3=$RC11_3)"
  fi
fi
```

- **Ожидаемый результат:** 11.1 — отказ с сообщением о неверном пароле
  GPG (код НЕ 0); 11.2 — отказ с сообщением о повреждении (код НЕ 0);
  11.3 — проверка проходит (код 0, оригинал не затронут); поврежденная
  копия удалена.
- **Признаки ошибки:** если 11.1/11.2 завершились кодом 0 — КРИТИЧЕСКИЙ
  дефект (программа выдает успех на испорченных данных); если 11.3
  упал — повреждение оригинала (критический дефект).
- **Способ остановки:** все операции — только верификация (чтение архива);
  изменяется лишь временная копия в каталоге приемки.
- **Очистка временных объектов:** поврежденная копия
  `$BBM_ACC_DIR/damaged-copy.gz.gpg` удаляется в блоке сразу после 11.2
  (в обеих ветках результата).

**Статус группы: УСПЕХ — все три признака; иначе ОШИБКА (дальше не
переходить).**

**Что прислать:** вывод блока целиком.

- **Способ остановки:** скрипт только читает систему.
- **Очистка временных объектов:** отчет находится в каталоге приемки
  (700) и удаляется группой 13 вместе с ним.

**Статус группы: УСПЕХ — отчет сформирован; иначе ОШИБКА.**

**Что прислать:** вывод блока целиком (отчет напечатан командой cat).

## Группа 13. Очистка временных объектов приемки

- **Цель:** удалить ВСЕ временные файлы приемки (каталог приемки и файл
  указателя). Целевые результаты теста (архивы, снапшоты, восстановленный
  subvolume) НЕ удаляются — это ваши данные на тестовой ФС.
- **Правила безопасности группы:** перед `rm -rf` доказывается
  принадлежность каталога текущему запуску. Требуются ОДНОВРЕМЕННО:
  (1) указатель — обычный файл (НЕ символическая ссылка) ровно из
  двух строк: путь каталога приемки и уникальный случайный
  идентификатор запуска, сгенерированный группой 1; (2) путь из
  первой строки соответствует шаблону `/tmp/bbm-acceptance.XXXXXX`;
  (3) это существующий каталог и НЕ символическая ссылка; (4) его
  realpath лежит в `/tmp` под тем же шаблоном; (5) внутри каталога
  есть `run-id.txt` (обычный файл, не симлинк), и его содержимое
  СОВПАДАЕТ с идентификатором запуска из указателя — именно это
  связывает удаляемый каталог с запуском, записавшим указатель;
  (6) внутри есть маркер `fs-uuid.txt` (обычный файл, не симлинк), и
  UUID маркера совпадает с эталонным UUID тестовой ФС. Любая
  неоднозначность — отказ от удаления, ничего не удаляется.

```bash
if [ -L /tmp/bbm-acceptance.dir ]; then
  echo "ГРУППА 13: ОТКАЗ — /tmp/bbm-acceptance.dir является символической ссылкой (в том числе висячей); по ссылкам не следую, ничего не удаляю. Пришлите вывод"
elif [ ! -f /tmp/bbm-acceptance.dir ]; then
  echo "Каталог приемки не найден или указатель не является обычным файлом (группа 1 не выполнялась)"
else
  BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir)
  PTR_RUN_ID=$(sed -n '2p' /tmp/bbm-acceptance.dir)
  PTR_LINES=$(wc -l < /tmp/bbm-acceptance.dir)
  REF_UUID=""
  if [ -L /tmp/bbm-test-fs.uuid ]; then
    echo "13: /tmp/bbm-test-fs.uuid — символическая ссылка; эталон из нее не читаю (сверка невозможна — будет ОТКАЗ)"
  elif [ -f /tmp/bbm-test-fs.uuid ]; then
    REF_UUID=$(cat /tmp/bbm-test-fs.uuid)
  fi
  G13="OK"
  if [ "$PTR_LINES" -ne 2 ]; then
    echo "13: ОТКАЗ — указатель обязан содержать ровно две строки (путь каталога и идентификатор запуска), фактически строк: $PTR_LINES; НЕ удаляю"
    G13="FAIL"
  fi
  if [ "$G13" = "OK" ] && [ -z "$PTR_RUN_ID" ]; then
    echo "13: ОТКАЗ — идентификатор запуска (вторая строка указателя) отсутствует; НЕ удаляю"
    G13="FAIL"
  fi
  if [ "$G13" = "OK" ]; then
    case "$BBM_ACC_DIR" in
      /tmp/bbm-acceptance.??????) ;;
      *)
        echo "13: ОТКАЗ — путь из указателя не соответствует шаблону /tmp/bbm-acceptance.XXXXXX: '$BBM_ACC_DIR'; НЕ удаляю"
        G13="FAIL" ;;
    esac
  fi
  if [ "$G13" = "OK" ]; then
    if [ -L "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
      echo "13: ОТКАЗ — '$BBM_ACC_DIR' не является существующим каталогом (или символическая ссылка); НЕ удаляю"
      G13="FAIL"
    fi
  fi
  if [ "$G13" = "OK" ]; then
    REAL_ACC=$(realpath -e "$BBM_ACC_DIR" 2>/dev/null)
    case "$REAL_ACC" in
      /tmp/bbm-acceptance.??????) ;;
      *)
        echo "13: ОТКАЗ — реальный путь вне служебного префикса /tmp: '$REAL_ACC'; НЕ удаляю"
        G13="FAIL" ;;
    esac
  fi
  # идентификатор запуска: связывает удаляемый каталог именно с тем запуском,
  # который записал указатель (совпадение указатель <-> run-id.txt)
  if [ "$G13" = "OK" ]; then
    if [ -L "$BBM_ACC_DIR/run-id.txt" ]; then
      echo "13: ОТКАЗ — $BBM_ACC_DIR/run-id.txt — символическая ссылка; НЕ удаляю"
      G13="FAIL"
    elif [ ! -f "$BBM_ACC_DIR/run-id.txt" ]; then
      echo "13: ОТКАЗ — в каталоге нет идентификатора запуска run-id.txt: принадлежность текущему запуску не доказана; НЕ удаляю"
      G13="FAIL"
    elif [ "$(cat "$BBM_ACC_DIR/run-id.txt")" != "$PTR_RUN_ID" ]; then
      echo "13: ОТКАЗ — идентификатор запуска в каталоге (run-id.txt) не совпадает с идентификатором в указателе: каталог НЕ принадлежит запуску, записавшему указатель; НЕ удаляю"
      G13="FAIL"
    fi
  fi
  if [ "$G13" = "OK" ]; then
    if [ -L "$BBM_ACC_DIR/fs-uuid.txt" ]; then
      echo "13: ОТКАЗ — $BBM_ACC_DIR/fs-uuid.txt — символическая ссылка; НЕ удаляю"
      G13="FAIL"
    elif [ ! -f "$BBM_ACC_DIR/fs-uuid.txt" ]; then
      echo "13: ОТКАЗ — в каталоге нет маркера fs-uuid.txt: принадлежность текущей приемке не доказана; НЕ удаляю"
      G13="FAIL"
    fi
  fi
  if [ "$G13" = "OK" ]; then
    if [ -z "$REF_UUID" ]; then
      echo "13: ОТКАЗ — эталонный UUID (/tmp/bbm-test-fs.uuid) недоступен: сверка невозможна; НЕ удаляю"
      G13="FAIL"
    elif [ "$(cat "$BBM_ACC_DIR/fs-uuid.txt")" != "$REF_UUID" ]; then
      echo "13: ОТКАЗ — UUID маркера не совпадает с эталонным UUID тестовой ФС: каталог НЕ принадлежит текущей приемке; НЕ удаляю"
      G13="FAIL"
    fi
  fi
  if [ "$G13" = "OK" ]; then
    echo "Доказательство принадлежности текущему запуску: указатель — обычный файл из двух строк; путь по шаблону; каталог, не симлинк; realpath в /tmp; идентификатор запуска указателя СОВПАДАЕТ с run-id.txt каталога; маркер fs-uuid; совпадение с эталонным UUID."
    echo "Содержимое каталога приемки перед удалением:"
    ls -laA "$BBM_ACC_DIR"
    rm -rf "$BBM_ACC_DIR"
    rm -f /tmp/bbm-acceptance.dir
    echo "Каталог приемки и файл указателя удалены: $BBM_ACC_DIR"
    echo "ГРУППА 13: УСПЕХ — временные объекты приемки удалены (доказательство получено)"
  else
    echo "ГРУППА 13: ОТКАЗ — при неоднозначности ничего не удаляется; пришлите вывод"
  fi
fi
echo "Осталось по желанию (ваши тестовые данные, не временные файлы):"
echo "  - снапшоты:        /mnt/btrfs-test/.snapshots/<имя>"
echo "  - архивы:          /mnt/btrfs-test/.snapshots/backup/"
echo "  - восстановленное: /mnt/btrfs-test/restore-target/<имя>"
echo "  - объекты группы 14: /mnt/btrfs-test/.top-snaps, /mnt/btrfs-test/top-restore (если выполнялась)"
echo "Эти объекты можно удалить позже вручную: sudo btrfs subvolume delete <путь>"
echo "(изменение свойства ro перед delete НЕ требуется)"
```

- **Ожидаемый результат:** каталог приемки и файл указателя удалены;
  перечислены оставшиеся целевые объекты теста.
- **Признаки ошибки:** не выполнен любой из пунктов доказательства
  (указатель — обычный файл из двух строк, шаблон пути, не симлинк,
  realpath, совпадение идентификатора запуска указателя и каталога,
  маркер fs-uuid, эталонный UUID) — удаление ОТКАЗАНО: путь из `/tmp`
  никогда не попадает в `rm -rf` без доказательства принадлежности
  текущему запуску (идентификатор запуска связывает удаляемый каталог
  с указателем, записанным группой 1 того же запуска).
- **Способ остановки:** группа удаляет только доказанный каталог
  приемки этого прогона.
- **Очистка временных объектов:** сама группа и есть очистка; эталонный
  файл `/tmp/bbm-test-fs.uuid` сохраняется для сверки UUID при следующих
  прогонах (никогда не перезаписывается).

**Статус группы: УСПЕХ — временные объекты удалены; ОТКАЗ/ОШИБКА —
обоснованный отказ с выводом (пришлите его).**

## Группа 14. Источник — верхний уровень Btrfs (subvolid=5)

- **Цель:** проверить реальную поддержку операций для источника
  subvolid=5: `btrfs subvolume show`, `btrfs subvolume snapshot -r`,
  `btrfs send`; предупреждение программы; отказ при обычном каталоге
  снапшотов внутри источника; успех при отдельном subvolume; вложенный
  subvolume НЕ попадает в архив. Никакой фиктивной успешной копии: при
  неподдержке операции (старое ядро/btrfs-progs) группа честно
  завершается ОШИБКОЙ/ПРОПУЩЕНО.
- **Предварительные условия:** группа 1 — УСПЕХ; группы 2-11 выполнены
  (группа меняет только НОВЫЕ объекты тестовой ФС, перечисленные в
  группе 13).
- **Правила безопасности группы:** rootid точки монтирования ≠ 5 (или
  не определен) — ВСЯ группа прекращается ДО своих блоков (ПРОПУЩЕНО/
  ОШИБКА), остальные блоки группы НЕ выполняются. Существующие
  `top-note.txt`, `.top-snaps`, `top-restore` (в том числе ПУСТОЙ
  каталог, файл или символическая ссылка, включая висячую) —
  немедленный стоп без перезаписи и без удаления: существующее не
  переиспользуется. Ошибка `btrfs subvolume create` останавливает
  группу: никакие файлы больше не создаются.

14.а Отрицательная проверка: обычный каталог снапшотов внутри источника
(верхнего уровня) — программа обязана ОТКАЗАТЬСЯ:

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
TOP_ROOTID=$(sudo btrfs inspect-internal rootid /mnt/btrfs-test 2>/dev/null)
if [ -z "$TOP_ROOTID" ]; then
  echo "ГРУППА 14: ОШИБКА — не удалось определить rootid точки монтирования; СТОП"
elif [ "$TOP_ROOTID" != "5" ]; then
  echo "ГРУППА 14: ПРОПУЩЕНО — /mnt/btrfs-test смонтирован не как верхний уровень (rootid=$TOP_ROOTID); вся группа 14 прекращается, остальные блоки НЕ выполняйте"
elif [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
  echo "ГРУППА 14 (14.а): ПРОПУЩЕНО — нет каталога приемки (группа 1 не выполнена)"
elif [ -e "$BBM_ACC_DIR/top-plain.py" ] || [ -L "$BBM_ACC_DIR/top-plain.py" ]; then
  echo "ГРУППА 14 (14.а): ОШИБКА — $BBM_ACC_DIR/top-plain.py уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
else
  # файл настроек — в каталоге приемки (отсутствие проверено выше, включая висячие симлинки)
  cat > "$BBM_ACC_DIR/top-plain.py" <<'EOF'
SUBVOLUMES = [{"name": "toplevel", "source": "/mnt/btrfs-test",
               "snapshot_dir": "/mnt/btrfs-test/.snapshots",
               "local_backup_dir": "/mnt/btrfs-test/.snapshots/backup"}]
SNAPSHOT_DIR = "/mnt/btrfs-test/.snapshots"
LOCAL_BACKUP_DIR = "/mnt/btrfs-test/.snapshots/backup"
GPG_PASSWORD = "acceptance-2026"
NETWORK_ENABLED = False
NETWORK_MOUNT = None
COMPRESSION = "gzip"
EOF
  cd /opt/btrfs-backup-manager
  sudo python3 main.py backup -n --config "$BBM_ACC_DIR/top-plain.py"
  RC14A=$?
  echo "14.а код возврата: $RC14A (должен быть НЕ 0: обычный каталог внутри источника верхнего уровня запрещен; ожидается сообщение про отдельный subvolume)"
  if [ "$RC14A" -eq 0 ]; then
    echo "14.а: ОШИБКА — программа приняла обычный каталог: фиктивный успех НЕ объявляется"
  fi
  # ничего не должно появиться поверх существующих данных:
  ls -laA /mnt/btrfs-test/.snapshots | head -5
fi
```

14.б Положительная проверка: каталог снапшотов — ОТДЕЛЬНЫЙ subvolume:

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
TOP_ROOTID=$(sudo btrfs inspect-internal rootid /mnt/btrfs-test 2>/dev/null)
G14B="УСПЕХ"
if [ -z "$TOP_ROOTID" ]; then
  echo "ГРУППА 14 (14.б): ОШИБКА — не удалось определить rootid; СТОП"
  G14B="ОШИБКА"
elif [ "$TOP_ROOTID" != "5" ]; then
  echo "ГРУППА 14 (14.б): ПРОПУЩЕНО — точка монтирования не верхний уровень (rootid=$TOP_ROOTID)"
  G14B="ПРОПУЩЕНО"
elif [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
  echo "ГРУППА 14 (14.б): ПРОПУЩЕНО — нет каталога приемки"
  G14B="ПРОПУЩЕНО"
elif [ -e /mnt/btrfs-test/.top-snaps ] || [ -L /mnt/btrfs-test/.top-snaps ]; then
  echo "14.б: ОШИБКА — /mnt/btrfs-test/.top-snaps уже существует (файл, каталог или символическая ссылка, включая висячую; след прошлого запуска); НЕ перезаписываю, группа остановлена. Пришлите список"
  G14B="ОШИБКА"
elif [ -e /mnt/btrfs-test/top-note.txt ] || [ -L /mnt/btrfs-test/top-note.txt ]; then
  echo "14.б: ОШИБКА — /mnt/btrfs-test/top-note.txt уже существует (файл, каталог или символическая ссылка, включая висячую; след прошлого запуска); НЕ перезаписываю, группа остановлена. Пришлите список"
  G14B="ОШИБКА"
elif [ -e "$BBM_ACC_DIR/top-subvol.py" ] || [ -L "$BBM_ACC_DIR/top-subvol.py" ]; then
  echo "14.б: ОШИБКА — $BBM_ACC_DIR/top-subvol.py уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
  G14B="ОШИБКА"
fi

if [ "$G14B" = "УСПЕХ" ]; then
  # отдельный subvolume каталога снапшотов; ошибка создания останавливает группу
  if sudo btrfs subvolume create /mnt/btrfs-test/.top-snaps; then
    if sudo btrfs subvolume show /mnt/btrfs-test/.top-snaps > /dev/null 2>&1; then
      echo "14.б: OK — .top-snaps создан как отдельный subvolume и подтвержден"
    else
      echo "14.б: ОШИБКА — после создания subvolume show не подтверждает объект; группа остановлена"
      G14B="ОШИБКА"
    fi
  else
    echo "14.б: ОШИБКА — btrfs subvolume create завершился с ошибкой; группа остановлена, ничего больше не создается"
    G14B="ОШИБКА"
  fi
fi

if [ "$G14B" = "УСПЕХ" ]; then
  # файл верхнего уровня (создан только что — существование проверено выше)
  echo "toplevel data" | sudo tee /mnt/btrfs-test/top-note.txt > /dev/null
  cat > "$BBM_ACC_DIR/top-subvol.py" <<'EOF'
SUBVOLUMES = [{"name": "toplevel", "source": "/mnt/btrfs-test",
               "snapshot_dir": "/mnt/btrfs-test/.top-snaps",
               "local_backup_dir": "/mnt/btrfs-test/.top-snaps/backup"}]
SNAPSHOT_DIR = "/mnt/btrfs-test/.top-snaps"
LOCAL_BACKUP_DIR = "/mnt/btrfs-test/.top-snaps/backup"
GPG_PASSWORD = "acceptance-2026"
NETWORK_ENABLED = False
NETWORK_MOUNT = None
COMPRESSION = "gzip"
EOF
  TOP_BEFORE=$(ls -1 /mnt/btrfs-test/.top-snaps/backup/*.gz.gpg 2>/dev/null | sort)
  cd /opt/btrfs-backup-manager
  sudo python3 main.py backup -n --config "$BBM_ACC_DIR/top-subvol.py"
  RC14B=$?
  if [ "$RC14B" -ne 0 ]; then
    echo "14.б: ОШИБКА — backup верхнего уровня не выполнен (код $RC14B); фиктивный успех не объявляется"
    G14B="ОШИБКА"
  else
    TOP_AFTER=$(ls -1 /mnt/btrfs-test/.top-snaps/backup/*.gz.gpg 2>/dev/null | sort)
    NEW_TOP=$(comm -13 <(printf '%s\n' "$TOP_BEFORE") <(printf '%s\n' "$TOP_AFTER"))
    NEW_TOP_COUNT=$(printf '%s\n' "$NEW_TOP" | grep -c .)
    if [ "${NEW_TOP_COUNT:-0}" -ne 1 ]; then
      echo "14.б: ОШИБКА — новых архивов верхнего уровня: ${NEW_TOP_COUNT:-0} (ожидался 1); успех НЕ объявляется"
      G14B="ОШИБКА"
    else
      TOP_ARCHIVE=$(printf '%s\n' "$NEW_TOP" | head -1)
      echo "Архив верхнего уровня (новый, отсутствовавший до): $TOP_ARCHIVE"
    fi
  fi
fi

if [ "$G14B" = "УСПЕХ" ]; then
  if [ -e /mnt/btrfs-test/top-restore ] || [ -L /mnt/btrfs-test/top-restore ]; then
    echo "14.б: ОШИБКА — /mnt/btrfs-test/top-restore уже существует (в том числе ПУСТОЙ каталог, файл или символическая ссылка); НЕ удаляю и НЕ переиспользую, восстановление отменено. Пришлите список"
    G14B="ОШИБКА"
  else
    sudo mkdir /mnt/btrfs-test/top-restore
    sudo python3 main.py restore --archive "$TOP_ARCHIVE" --target /mnt/btrfs-test/top-restore --config "$BBM_ACC_DIR/top-subvol.py"
    RC14R=$?
    if [ "$RC14R" -ne 0 ]; then
      echo "14.б: ОШИБКА — восстановление верхнего уровня завершилось с кодом $RC14R"
      G14B="ОШИБКА"
    fi
  fi
fi

if [ "$G14B" = "УСПЕХ" ]; then
  TOP_RCVD="/mnt/btrfs-test/top-restore/$(basename "$TOP_ARCHIVE" .gz.gpg)"
  echo "--- содержимое восстановленного верхнего уровня:"
  ls -laA "$TOP_RCVD"
  if [ -f "$TOP_RCVD/top-note.txt" ] && [ ! -e "$TOP_RCVD/source/README.txt" ] \
     && [ ! -e "$TOP_RCVD/source/random.bin" ]; then
    echo "14.в: ОК — файл верхнего уровня восстановлен; вложенный subvolume source в архив НЕ попал (ожидаемое поведение Btrfs)"
  else
    echo "14.в: ОШИБКА — проверьте список выше: файл верхнего уровня обязан присутствовать, вложенный subvolume — отсутствовать"
    G14B="ОШИБКА"
  fi
fi
echo "ГРУППА 14: $G14B"
```

- **Ожидаемый результат:** 14.а — отказ (код НЕ 0) с объяснением;
  14.б — успешный backup и restore; в восстановленном верхнем уровне
  есть `top-note.txt` и НЕТ содержимого вложенного `source` (пустой
  каталог допустим).
- **Признаки ошибки:** код 0 в 14.а (программа приняла обычный каталог
  внутри источника верхнего уровня); существующие top-note.txt /
  .top-snaps / top-restore (в том числе пустой каталог, файл или
  символическая ссылка, включая висячую) — СТОП без перезаписи и без
  удаления; ошибка `btrfs subvolume create` — группа остановлена;
  отсутствие top-note.txt или наличие файлов source в 14.в;
  сообщения btrfs о неподдержке операции — честная ОШИБКА/ПРОПУЩЕНО
  с пояснением версии ядра/btrfs-progs.
- **Способ остановки:** группа создает только новые объекты
  (`.top-snaps`, `top-restore`, `top-note.txt`) с отказом от
  перезаписи существующих; при rootid≠5 вся группа прекращается до
  своих блоков.
- **Очистка временных объектов:** файлы настроек — в каталоге приемки
  (удаляются группой 13); объекты тестовой ФС перечислены в группе 13
  (удаляются вручную по желанию).

**Статус группы: УСПЕХ / ОШИБКА / ПРОПУЩЕНО (rootid≠5 — вся группа
прекращается; неподдержка операций).**

**Что прислать:** вывод обоих блоков.

## Группа 15. Разные файловые системы: отказ вместо смешивания

- **Цель:** источник на тестовой Btrfs, каталог снапшотов глобально
  указан на ДРУГОЙ файловой системе — программа обязана ОТКАЗАТЬСЯ ДО
  создания снапшотов, ничего не создать ни на чужой ФС, ни на тестовой,
  и объяснить причину. Проверка изоляции нескольких Btrfs: смешивание
  файловых систем запрещено.

```bash
BBM_ACC_DIR=$(head -n 1 /tmp/bbm-acceptance.dir 2>/dev/null)
G15="УСПЕХ"
if [ -z "$BBM_ACC_DIR" ] || [ ! -d "$BBM_ACC_DIR" ]; then
  echo "ГРУППА 15: ПРОПУЩЕНО — нет каталога приемки (группа 1 не выполнена)"
  G15="ПРОПУЩЕНО"
elif [ -e /snapshots-on-main-fs ] || [ -L /snapshots-on-main-fs ]; then
  echo "ГРУППА 15: ОШИБКА — /snapshots-on-main-fs уже существует на основной ФС (файл, каталог или символическая ссылка, включая висячую); НЕ перезаписываю и НЕ удаляю. Пришлите ls -laA /snapshots-on-main-fs"
  G15="ОШИБКА"
elif [ -e "$BBM_ACC_DIR/wrong-fs.py" ] || [ -L "$BBM_ACC_DIR/wrong-fs.py" ]; then
  echo "ГРУППА 15: ОШИБКА — $BBM_ACC_DIR/wrong-fs.py уже существует: перезапись запрещена, повторный запуск группы в том же прогоне не допускается. Пришлите ls -laA $BBM_ACC_DIR"
  G15="ОШИБКА"
else
  # файл настроек — в каталоге приемки (отсутствие проверено выше, включая висячие симлинки)
  cat > "$BBM_ACC_DIR/wrong-fs.py" <<'EOF'
SUBVOLUMES = [{"name": "src", "source": "/mnt/btrfs-test/source"}]
SNAPSHOT_DIR = "/snapshots-on-main-fs"
LOCAL_BACKUP_DIR = "/snapshots-on-main-fs/backup"
GPG_PASSWORD = "acceptance-2026"
NETWORK_ENABLED = False
NETWORK_MOUNT = None
COMPRESSION = "gzip"
EOF
  BEFORE_SNAPS=$(ls -1 /mnt/btrfs-test/.snapshots 2>/dev/null | wc -l)
  cd /opt/btrfs-backup-manager
  sudo python3 main.py backup -n --config "$BBM_ACC_DIR/wrong-fs.py"
  RC15=$?
  AFTER_SNAPS=$(ls -1 /mnt/btrfs-test/.snapshots 2>/dev/null | wc -l)
  echo "код возврата: $RC15 (должен быть НЕ 0); снапшотов до: $BEFORE_SNAPS, после: $AFTER_SNAPS (должны быть равны)"
  if [ "$RC15" -eq 0 ]; then
    echo "15: ОШИБКА — программа «успешно» резервировала с каталогом на чужой ФС"
    G15="ОШИБКА"
  elif [ "$BEFORE_SNAPS" != "$AFTER_SNAPS" ]; then
    echo "15: ОШИБКА — число снапшотов тестовой ФС изменилось ($BEFORE_SNAPS -> $AFTER_SNAPS)"
    G15="ОШИБКА"
  elif [ -e /snapshots-on-main-fs ] || [ -L /snapshots-on-main-fs ]; then
    echo "15: ОШИБКА — на основной ФС появился объект /snapshots-on-main-fs"
    G15="ОШИБКА"
  else
    echo "15: ОК — отказ ДО операции; каталог на чужой ФС НЕ создан; снапшоты тестовой ФС не тронуты"
  fi
fi
echo "ГРУППА 15: $G15 — программа не смешивает файловые системы"
```

- **Ожидаемый результат:** код НЕ 0; сообщение про РАЗНЫЕ файловые
  системы Btrfs; `/snapshots-on-main-fs` не создан; количество снапшотов
  в `/mnt/btrfs-test/.snapshots` не изменилось.
- **Признаки ошибки:** код 0 (программа «успешно» резервировала с
  каталогом на чужой ФС); появился каталог на основной ФС; изменилось
  число снапшотов; существующий `/snapshots-on-main-fs` на старте
  (в том числе висячая символическая ссылка) — СТОП (не
  перезаписываю).
- **Способ остановки:** группа только запускает программу и читает
  списки; при корректном поведении ничего не изменяется.
- **Очистка временных объектов:** файл настроек — в каталоге приемки
  (удаляется группой 13 вместе с ним).

**Статус группы: УСПЕХ — отказ без побочных эффектов; иначе ОШИБКА.**

**Что прислать:** вывод блока.

## Что считается успешной приемкой

- группы 1-9, 11, 12, 13, 15 — статус УСПЕХ;
- группа 1 — УСПЕХ только при совпадении заранее известного UUID
  (файл прошлого прогона или ввод оператора) с результатами ДВУХ
  независимых запросов; обнаруженный на /dev/loop0 UUID эталоном
  не является;
- группа 8 — УСПЕХ для каждого доступного алгоритма (zstd-ветка может
  быть честно ПРОПУЩЕНО только при отсутствии zstd);
- группа 10 — УСПЕХ, если zstd установлен, иначе честно ПРОПУЩЕНО;
- группа 14 — УСПЕХ; rootid≠5 прекращает ВСЮ группу до ее блоков
  (ПРОПУЩЕНО); неподдержка операции текущим ядром или btrfs-progs —
  честная ОШИБКА/ПРОПУЩЕНО с пояснением версии;
- ПРОПУЩЕНО допустимо только при отсутствии предварительных условий —
  и никогда не выдается за успех;
- любое расхождение сравнения, «мусорные» пути в обнаружении, отказ
  конвейера, «успех» на испорченных данных, нулевой код возврата при
  ненайденном результате — дефект, версия не принимается;
- после статуса `ОШИБКА` следующая группа НЕ выполняется: пришлите
  вывод и дождитесь анализа.
