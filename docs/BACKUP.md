# Резервное копирование

Короткая самостоятельная инструкция. Общие сведения — в
[README.md](../README.md); установка — в [INSTALL.md](INSTALL.md).

## Что важно знать о Btrfs

- **Read-only снапшот** — зафиксированная копия subvolume на момент
  создания. Программа создает ее командой `btrfs subvolume snapshot -r`
  и архивирует именно снапшот: данные источника продолжают изменяться,
  а архив остается согласован на одну точку времени.
- **Архив** — зашифрованный файл: поток `btrfs send` пропускается через
  сжатие (gzip/zstd) и шифрование GPG. Каждый архив несет SHA-256 и
  проверяется сразу после создания.
- **Что резервируется отдельно.** Снапшот и `btrfs send` работают с
  ОДНИМ subvolume. Вложенные subvolume НЕ входят в снапшот родителя:
  чтобы резервировать `/@home`, его указывают отдельным источником.
- **Верхний уровень Btrfs (subvolid=5)** можно выбрать источником —
  программа предупредит, что вложенные subvolume в снапшот не попадут,
  и потребует подтвердить выбор.

## Из TUI

```bash
sudo python3 main.py tui
```

1. Пункт «Резервное копирование» (клавиша 1).
2. Отметьте источники (Пробел — переключить, A — все/ничего, R —
   обновить список, Enter — продолжить).
3. Для каждого источника проверяются каталоги снапшотов и архивов.
   Проблемные источники показываются с причиной: исключить (1),
   принять предложенный каталог (A) или указать свой путь (E).
   Выбранные пути относятся к текущей операции и не записываются
   в конфигурацию.
4. Подтвердите итоговые параметры, выберите алгоритм сжатия, введите
   пароль GPG (скрытый ввод, дважды).
5. Экран показывает этапы и итог; по завершении можно посмотреть
   копии в пункте «Локальные снапшоты».

## Из командной строки

```bash
sudo python3 main.py backup            # интерактивный запуск
sudo python3 main.py backup -n         # строго по конфигурации (cron)
sudo python3 main.py backup -n --subvolume home     # один источник
sudo python3 main.py backup --config /etc/bbm/home.py   # другой файл настроек
```

## Каталоги

- Снапшоты и архивы размещаются на той же файловой системе Btrfs, что
  и источник (проверяется по UUID); каталог снапшотов не должен лежать
  внутри самого источника — иначе каждый снапшот включал бы предыдущие.
  Допустимое исключение — каталог снапшотов как отдельный subvolume.
- У каждого источника могут быть собственные `snapshot_dir` и
  `local_backup_dir` (в словаре `SUBVOLUMES`); без них используются
  общие `SNAPSHOT_DIR` / `LOCAL_BACKUP_DIR`.

## Проверка и хранение

- Каждый архив проверяется сразу: расшифрование, тест сжатого потока,
  SHA-256. Непроверенный архив не считается готовым.
- Сетевая копия (если настроена): архив копируется на шару, SHA-256
  сверяется повторно; локальный архив удаляется только после
  подтвержденной сетевой копии. При любой ошибке локальный архив
  сохраняется.
- Retention хранит последние `RETENTION_COUNT` проверенных копий
  каждого источника; удаление сверх этого числа выполняется только при
  подтвержденной сетевой копии, при неоднозначности копия сохраняется.
