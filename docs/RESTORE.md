# Восстановление данных

Восстановление — критически важная операция: перед восстановлением в
существующий каталог программа запрашивает подтверждение и защищает
уже имеющиеся данные от случайной перезаписи.

## Источники восстановления

1. **Локальный архив** — файл `.gz.gpg` / `.zst.gpg` из каталога
   локальных архивов.
2. **Сетевой архив** — файл из каталога сетевой шары (шара должна быть
   смонтирована заранее).
3. **Локальный read-only снапшот** — снапшот в каталоге снапшотов.

## Восстановление из архива (TUI)

```bash
sudo python3 main.py tui
```

Пункт «Восстановление» → выберите источник → укажите целевой каталог на
Btrfs → подтвердите → введите пароль (если требуется).

## Восстановление из архива (командная строка)

```bash
sudo python3 main.py restore --archive /var/backups/btrfs/home/home_2026-11-08_030000_ab12cd.gz.gpg --target /mnt/restore
```

Без аргументов запускается интерактивный выбор архива. Список доступных
архивов с датами и состояниями — пункт «Локальные снапшоты» → «Локальные
архивы» в TUI/CLI-меню или `python3 main.py list-archives`.

## Что происходит при восстановлении

1. Проверка наличия архива и чтение метаданных (JSON рядом с архивом).
2. Проверка контрольной суммы SHA-256, если она есть в метаданных.
3. Запрос пароля (если пароль не задан в конфигурации).
4. Расшифрование потока (GPG, пароль передается через `--passphrase-fd`,
   не попадая в argv).
5. Определение алгоритма сжатия ПО САМОМУ АРХИВУ (расширение и
   метаданные). Текущее значение `COMPRESSION` в конфигурации не
   используется — архивы gzip восстанавливаются при настройке zstd и
   наоборот.
6. Распаковка потока.
7. `btrfs receive` в целевой каталог — создается subvolume с именем
   снапшота (существующие объекты не перезаписываются).
8. Проверка результата. При ошибке ПРИЕМА частичный subvolume НЕ
   удаляется автоматически: программа сообщает точную причину и
   предлагает проверить и удалить только объект ТЕКУЩЕЙ операции
   (напрямую `btrfs subvolume delete`, без смены свойства ro).

## Восстановление из локального снапшота

Программа проверяет, что источник — действительно Btrfs subvolume и что
он read-only (`ro=True` подтверждается `btrfs property get`); затем
создает записываемую копию в целевом каталоге. Если целевой подvol
уже существует, операция требует явного подтверждения и не перезаписывает
данные молча.

```bash
sudo python3 main.py tui   # Восстановление → Из локального снапшота
```

## Проверка архива без восстановления

```bash
sudo python3 main.py verify --archive /путь/имя.gz.gpg
```

Команда проверяет размер, SHA-256, расшифрование и сжатый поток и
показывает фактический алгоритм сжатия.

## Полное восстановление операционной системы

Восстановление отдельного subvolume и полное восстановление ОС — разные
задачи. `btrfs send` одного subvolume не переносит вложенные subvolume,
таблицу разделов, EFI и загрузчик. См. `docs/FULL-SYSTEM-RESTORE.md`.

## Частые вопросы

- **«Архив не найден»** — проверьте путь; сетевые архивы требуют
  смонтированной шары.
- **Неправильный пароль** — архив расшифровывается тем паролем, которым
  был создан; он задается в конфигурации или вводится при операции.
- **«Поврежден архив» / SHA-256 не совпал** — восстановление отменяется;
  используйте другую копию (снапшот или сетевой архив).
- **Восстановление в существующий каталог** — потребуется подтверждение;
  существующие данные не затираются молча.
