# Автоматизация через cron

Короткая инструкция неинтерактивного запуска. Общие сведения — в
[README.md](../README.md); установка — в [INSTALL.md](INSTALL.md).

## Требования к неинтерактивному запуску

- Пароль GPG должен быть задан в файле настроек (`GPG_PASSWORD`): в
  cron никто не вводит пароль скрытым вводом, значение-заполнитель
  `CHANGE_ME` завершит операцию ошибкой. Файл настроек хранит пароль —
  держите права 600 и владельца root.
- `SUBVOLUMES`, `SNAPSHOT_DIR` и (если используется сеть) `NETWORK_MOUNT`
  должны быть заданы: неинтерактивные команды работают строго по
  конфигурации и не задают вопросов.
- Отсутствие сети — не ошибка: выполняется локальное копирование, архивы
  получают статус `upload-pending` и отправляются позже.
- Параллельный запуск не начнется повторно: блокировка flock.

## Пример /etc/cron.d/btrfs-backup

```cron
# Ежедневно в 03:15 — резервное копирование (основной файл настроек)
15 3 * * * root cd /opt/btrfs-backup-manager && /usr/bin/python3 main.py backup -n >> /var/log/bbm-cron.log 2>&1

# Ежечасно — отправка архивов, ожидающих сеть
0 * * * * root cd /opt/btrfs-backup-manager && /usr/bin/python3 main.py upload-pending -n >> /var/log/bbm-cron.log 2>&1

# Еженедельно в воскресенье 04:30 — отдельный файл настроек (другой
# набор источников, другое время журнала и блокировки)
30 4 * * 0 root cd /opt/btrfs-backup-manager && /usr/bin/python3 main.py backup -n --config /etc/bbm/home.py >> /var/log/bbm-home.log 2>&1
```

## Что делает каждая команда

- `backup -n` — полный цикл: снапшоты, архивы, проверка, отправка
  (если включена), retention.
- `upload-pending -n` — повторная отправка архивов, созданных при
  недоступной сети (проверка SHA-256 и содержимого перед отправкой).
- `verify --archive ПУТЬ` — проверка архива без восстановления.

## Сжатие

Неинтерактивный режим без вопросов использует `COMPRESSION`; при
отсутствии основной утилиты действует `COMPRESSION_FALLBACK`
(автоматический fallback отключается `CRON_COMPRESSION_FALLBACK = False`).

## Безопасность

- Пароль передается утилитам через файловый дескриптор
  (`--passphrase-fd`), не через argv: в журналах и процессах пароля нет.
- Сетевые архивы автоматически не удаляются; локальный архив удаляется
  только после подтвержденной сетевой копии.
- Retention удаляет снапшоты сверх `RETENTION_COUNT` только при
  подтвержденной сетевой копии; при неоднозначности копия сохраняется.
