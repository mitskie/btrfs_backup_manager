# Полное восстановление операционной системы

Этот документ описывает восстановление ВСЕЙ системы, а не отдельного
Btrfs subvolume. Btrfs Backup Manager создает резервные копии
subvolume; полный подъем системы на новом диске требует дополнительных
шагов, которые программа не выполняет автоматически.

## Чего не хватает в архиве одного subvolume

`btrfs send` переносит содержимое ОДНОГО subvolume. Не переносятся:

1. **Таблица разделов** диска (в том числе разметка GPT/MBR).
2. **EFI System Partition** (FAT32) и другие не-Btrfs разделы.
3. **Загрузчик** (GRUB/systemd-boot) и его настройки.
4. **Вложенные subvolume** — например, `@home` и `@log` внутри `@`:
   в снапшоте родителя они выглядят пустыми каталогами. Резервируйте
   каждый вложенный subvolume отдельным источником.
5. Системные разделы вне Btrfs (`/boot` на ext4 и т.п.).

## Планирование резервных копий для полного восстановления

Резервируйте КАЖДЫЙ subvolume системы как отдельный источник:

```python
SUBVOLUMES = [
    {"name": "root", "source": "/", "snapshot_dir": "/.snapshots"},
    {"name": "home", "source": "/home",
     "snapshot_dir": "/home/.snapshots",
     "local_backup_dir": "/var/backups/btrfs/home"},
]
```

Дополнительно сохраните вне Btrfs-архивов:

- вывод `lsblk -f`, `blkid`, `fstab` (`/etc/fstab` попадает в снапшот
  корня, но держите копию и вне машины);
- конфигурацию загрузчика (`/etc/default/grub`, `/boot/grub` — если
  `/boot` не отдельный subvolume, он входит в корень);
- список монтирований subvolume (`btrfs subvolume list /`).

## Схема восстановления системы

1. Загрузитесь с Live-CD/Live-USB с btrfs-progs.
2. Разметьте новый диск (таблица разделов, ESP, раздел Btrfs) —
   `gdisk`/`parted`, затем `mkfs.btrfs`.
3. Смонтируйте новый раздел в `/mnt/newroot`.
4. Восстановите каждый subvolume в нужное место:

   ```bash
   sudo python3 main.py restore \
       --archive /mnt/backup/root_....gz.gpg --target /mnt/newroot
   sudo python3 main.py restore \
       --archive /mnt/backup/home_....gz.gpg --target /mnt/newroot/home
   ```

   Точный набор и целевые точки монтирования соответствуют вашей
   разметке (`subvol=` в fstab).
5. Восстановите/пересоздайте ESP и загрузчик:

   ```bash
   # пример для GRUB (Debian/Ubuntu):
   sudo mount /dev/sda1 /mnt/newroot/boot/efi
   for d in dev proc sys; do sudo mount --bind /$d /mnt/newroot/$d; done
   sudo chroot /mnt/newroot
   grub-install
   update-grub
   exit
   ```

6. Проверьте `/etc/fstab` (UUID новых разделов), пересоздайте
   swapfile при необходимости.
7. Перезагрузка с нового диска; проверка данных.

## Отдельный subvolume против системы целиком

- Восстановление отдельного subvolume (например, случайно удаленный
  `/home`) выполняется командой restore в существующую систему — это
  основной сценарий программы.
- Полное восстановление ОС — ручная процедура администратора; архивы
  программы поставляют ДАННЫЕ subvolume, но не загружаемую систему.

## Проверка перед тем, как полагаться на копии

Регулярно выполняйте проверку восстановления на тестовой машине или в
виртуальной машине: восстановите корневой subvolume в VM и убедитесь,
что данных достаточно для загрузки. Один только успешный backup не
доказывает восстанавливаемость системы.
