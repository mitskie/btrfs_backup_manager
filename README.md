# Btrfs Backup Manager

Переносная программа для резервного копирования и восстановления **Btrfs subvolume** в Linux. Создаёт read-only снапшоты, формирует полные архивы через `btrfs send` (без инкрементальных копий), сжимает их с помощью gzip/zstd, шифрует симметричным GPG и проверяет целостность. При необходимости архивы копируются на заранее смонтированное сетевое хранилище.

Программа не устанавливается как системный пакет или служба: достаточно распаковать каталог проекта и запускать его вручную либо по расписанию. Python-зависимостей нет — используется стандартная библиотека.

## Возможности

- **Read-only снапшоты Btrfs.** Состояние исходного subvolume фиксируется на момент создания снапшота.
- **Полные резервные копии.** Используется `btrfs send`; инкрементальная передача не реализована.
- **Потоковая обработка.** Поток `btrfs send` проходит через сжатие и GPG без загрузки всего архива в оперативную память.
- **Сжатие gzip или zstd.** Алгоритм определяется по архиву при восстановлении. Если zstd недоступен, предусмотрен fallback на gzip.
- **Симметричное шифрование GPG (AES256).** Пароль передаётся через файловый дескриптор `--passphrase-fd`, а не через аргументы процесса или журналы.
- **Проверка архива.** При создании проверяются расшифрование, сжатый поток и SHA-256.
- **Локальное и сетевое хранение.** Архив сначала создаётся и проверяется локально; при включённой автоматической отправке он копируется на уже смонтированную шару с проверкой SHA-256.
- **Восстановление.** Поддерживается восстановление из локального или сетевого архива, а также из локального read-only снапшота. Восстановленный локальный снапшот создаётся как записываемый.
- **Retention.** Хранятся последние N проверенных копий каждого источника (по умолчанию 5). Неоднозначные случаи обрабатываются консервативно: программа не удаляет копии, если не может безопасно подтвердить условия.
- **Обнаружение Btrfs subvolume.** Показываются источники и устройства; верхний уровень файловой системы (`subvolid=5`) обозначается отдельно и требует явного выбора/подтверждения.
- **Несколько интерфейсов.** Полноэкранный TUI на curses, простой CLI-меню и команды для скриптов/cron.

## Системные требования

- Linux с поддержкой Btrfs.
- Python **3.12 или новее**.
- Права root для операций с Btrfs subvolume и `btrfs send/receive`.

## Системные утилиты

Установите системные утилиты (это не Python-пакеты):

| Утилита | Требование | Назначение |
| --- | --- | --- |
| `btrfs` (`btrfs-progs`) | Обязательно | Снапшоты, `send` и `receive` |
| `gpg` | Обязательно | Шифрование и проверка архивов |
| `gzip` | Обязательно | Сжатие и резервный алгоритм |
| `zstd` | Необязательно | Основной/альтернативный алгоритм сжатия |

Проверка окружения:

```bash
python3 main.py diagnostics
```

## Быстрый запуск

Склонируйте репозиторий GitHub или распакуйте архив релиза. Перейдите в корневой каталог проекта — туда, где находится `main.py`. Затем создайте рабочую конфигурацию из примера:

```bash
cp backup_config.py.example backup_config.py
$EDITOR backup_config.py
```

Настройте источники, каталоги, сетевое хранилище и пароль GPG. Затем запустите полноэкранный интерфейс:

```bash
doas python3 main.py tui
```

Вместо `doas` можно использовать `sudo`, если он применяется в вашем дистрибутиве. Без аргументов `python3 main.py` запускает простое CLI-меню. Если curses недоступен или терминал не поддерживает полноэкранный режим, TUI автоматически переходит к простому CLI-меню.

Справка по командам:

```bash
python3 main.py --help
```

Подробная инструкция по установке и запуску: [docs/INSTALL.md](docs/INSTALL.md).

## Конфигурация

Основной файл настроек — `backup_config.py`; пример — `backup_config.py.example`. Файл `config.py` вручную редактировать не нужно: он загружает и проверяет конфигурацию.

Основные параметры:

| Параметр | Назначение |
| --- | --- |
| `SUBVOLUMES` | Список источников: пути или словари с индивидуальными каталогами |
| `SNAPSHOT_DIR` | Каталог read-only снапшотов на той же Btrfs, что и источник |
| `LOCAL_BACKUP_DIR` | Каталог локальных архивов; `None` означает `SNAPSHOT_DIR/backup` |
| `COMPRESSION` | Основной алгоритм: `zstd` или `gzip` |
| `COMPRESSION_FALLBACK` | Резервный алгоритм сжатия |
| `GPG_PASSWORD` | Пароль шифрования; нужен для автоматического/неинтерактивного запуска |
| `NETWORK_ENABLED` | Включает или отключает сетевое хранилище |
| `NETWORK_MOUNT` | Точка монтирования сетевой шары |
| `NETWORK_DIRECTORY` | Подкаталог внутри сетевой шары |
| `AUTO_UPLOAD` | Автоматическая отправка после успешного backup |
| `RETENTION_COUNT` | Число проверенных копий для хранения на источник |

Для cron пароль GPG должен быть задан в конфигурации. В интерактивном режиме при создании архива пароль можно ввести скрыто. **Ручная отправка уже зашифрованных архивов на шару пароль GPG не запрашивает.**

Файл конфигурации может содержать секрет. Ограничьте права доступа, например:

```bash
doas chown root:root backup_config.py
doas chmod 600 backup_config.py
```

Вместо `doas` можно использовать `sudo`.

### Настройки интерактивного режима

TUI позволяет выбирать источники и параметры текущей операции. В частности, перед резервным копированием можно выбрать алгоритм сжатия и включить или отключить автоматическую отправку на шару **только для текущего запуска**. Это не изменяет `backup_config.py` и не влияет на CLI/cron: для них продолжают действовать настройки конфигурационного файла.

Если автоматическая отправка отключена или шара недоступна, архивы остаются локально в состоянии ожидания отправки (`upload-pending`).

## Резервное копирование

Интерактивный запуск:

```bash
doas python3 main.py tui
```

Или простой CLI:

```bash
doas python3 main.py backup
```

Неинтерактивный запуск строго по конфигурации (например, cron):

```bash
doas python3 main.py backup -n
```

Можно указать один или несколько источников, заданных в конфигурации:

```bash
doas python3 main.py backup --subvolume /
```

Цикл операции: проверка окружения → read-only снапшот → `btrfs send` → сжатие → GPG → проверка архива → сетевая отправка (если включена) → retention.

**Важно:** вложенные subvolume не входят в снапшот родительского subvolume. Если их нужно резервировать, укажите каждый из них отдельным источником.

Подробности: [docs/BACKUP.md](docs/BACKUP.md).

## Сетевая шара и отправка архивов

Программа **не монтирует и не размонтирует** сетевые файловые системы. Администратор должен смонтировать шару заранее. Программа проверяет точку монтирования и доступность сетевого каталога; сетевые архивы автоматически не удаляются.

Доступны два способа отправки:

1. **Автоматическая отправка при резервном копировании.** Управляется параметром `AUTO_UPLOAD`; в TUI его можно переопределить для текущей операции.
2. **Ручная отправка из TUI.** Откройте «Локальные снапшоты» → «Локальные архивы», отметьте нужные архивы клавишей `Пробел` и нажмите `U`. Клавиша `A` отмечает все архивы или снимает все отметки. Перед отправкой программа проверяет каждый выбранный архив:
   - если на NAS уже есть файл с тем же именем и SHA-256 совпадает, повторная передача пропускается;
   - если одноимённый файл существует, но SHA-256 отличается, перезапись запрещается;
   - если архив недоступен или проверка не пройдена, он исключается из отправки с указанием причины;
   - если остались архивы, которые можно отправить, программа показывает предварительный итог и запрашивает подтверждение.

Ручная отправка копирует готовые зашифрованные файлы `.gpg` без расшифрования и без запроса пароля GPG.

Для CLI/cron предусмотрена команда отправки локальных архивов, ожидающих передачи:

```bash
doas python3 main.py upload-pending
```

Подробности: [docs/BACKUP.md](docs/BACKUP.md) и [docs/CRON.md](docs/CRON.md).

## Восстановление

Из архива:

```bash
doas python3 main.py restore --archive /путь/к/архиву.gpg --target /каталог
```

Или выберите источник восстановления в интерактивном меню. Поддерживаются локальные архивы, сетевые архивы и локальные read-only снапшоты.

Восстановление из архива требует пароль GPG. Программа создаёт новый subvolume в целевом каталоге и не должна перезаписывать существующие данные. Алгоритм сжатия определяется автоматически по архиву.

Подробности: [docs/RESTORE.md](docs/RESTORE.md).

## Ограничения

- Используются только **полные** копии; инкрементальное резервирование не поддерживается.
- Вложенные subvolume не включаются в снапшот родительского subvolume.
- Сетевую шару нужно смонтировать заранее; программа не управляет монтированием.
- Резервная копия отдельного subvolume не является образом всего диска: в неё не входят таблица разделов, загрузчик и отдельные вложенные subvolume.
- Верхний уровень Btrfs (`subvolid=5`) — отдельный объект; содержимое вложенных subvolume в его снапшот не попадает.

План проверки на изолированной тестовой Btrfs описан в [docs/ACCEPTANCE-TEST.md](docs/ACCEPTANCE-TEST.md). Восстановление всей системы рассматривается отдельно: [docs/FULL-SYSTEM-RESTORE.md](docs/FULL-SYSTEM-RESTORE.md).
